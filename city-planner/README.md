# City Planner · 山海使用手册

Python + Electron 的本地俯视地形工作台。Python/NumPy 生成高度、湿度、汇水河网与真实河床，Electron Canvas 渲染地貌、光照、等高线及高程图。运行和导出不依赖云服务。

城市模式使用 Python/Shapely 处理道路拓扑、沿街地块和建筑，按月模拟家庭迁入、就业、出行、开发、地价及功能城区。所有地图与统计都读取后端同一份城市状态。

## 开始建设城市

1. 启动后进入主菜单，可选择「新建地图」「加载地图」或「设置」。「新建地图」进入地形准备阶段，调整参数或世界种子，点击「生成地形」预览；满意后点击「确认地形并开始规划」。程序会先自动保存独立的地形起点，保存成功后进入城市规划。设置可调整新地图的默认精度、显示样式、等高线和坐标网格。
2. 选择高速公路、快速路、普通路、小路或主干道，在地图逐点绘制平滑曲线或折线，按 Enter 或「完成绘制」提交。闭合道路形成街区，沿街可建设土地自动形成地块。跨水道路需要桥梁或隧道；高速公路、快速路、纯轨道和步道不直接产生沿街开发地块。小路既可手绘，也可由系统生成；选中已有道路可修改等级，宽度、速度、容量和接入规则一起改变。
3. 点击顶部「开始模拟」，拖动速度滑块观察人车、昼夜及施工、竣工、迁入与就业。道路不会立刻变出人口；住房和岗位需要先形成。默认自动补充社区支路、建筑小径、公园、广场和公共服务，并受地形影响。
4. 在「交通」设置巴士站，按顺序选择站点并开通线路。地铁、铁路、有轨电车需要先铺设兼容轨道，再设站和开线。可以设置间隔、容量、运营时间，点击线路调整运营。铁路客站和货场分别设置，区域边界终点支持对外客运；货运服务按吨位容量运行。
5. 在「观察」切换土地单价、租金、岗位可达性、交通流量、人口和功能城区。点击地块可看用途、建筑占地、总建筑面积、容量和价格历史；用途偏好影响后续开发。

自动设施按片区用途选址。污水处理厂、发电厂、回收中心和污染厂区只选择工业占主导的外围地块，避开商业中心、被建筑包围的空地，以及现有和规划住宅、学校、医院；没有合适场地时跳过生成。新规则不会搬迁旧存档中已有的设施。

医院、大学、酒店、工业及公用设施、机场、港口、火车站和停车设施均提供就业岗位，数量按类型与实际规模计算。岗位需接入道路才开放，参与居民求职、早晚通勤、住房需求、岗位可达性和全市就业统计；详情显示岗位上限、开放岗位、已就业人数和空缺。岗位与服务容量分开计数，例如标准规模污水厂为 45 个岗位、医院为 240 个岗位（游戏模拟参数）。旧存档载入时补充岗位数据，断路或拆除后停止招聘。
6. 使用「存档」或「文件」保存城市（也可按 Ctrl/Cmd+S）：首次手动保存必须命名，之后可新建独立存档或选择已有存档覆盖；新建时重名会提示，不会悄悄覆盖。「返回主菜单」提供保存后返回或放弃未保存修改的选择。主菜单「加载地图」列出地形起点、城市存档和自动保存。「文件」仍可导入导出 JSON；「观察」可以导出 CSV、记录基线及创建独立方案。

建筑按用途采用不同占地与长宽分布，同类建筑也大小不一。总建筑面积由真实建筑轮廓面积乘楼层得到，并用于空间容量和开发收益计算。现有模型包含同类用途集聚、办公核心高度梯度、需求约束的分期开发与加层，以及分服务范围的学校、公园和诊所。v5 将建筑靠街布置。v7 改为按实际街边长度和地形生成不等宽地块、偏心庭院、折转小巷和侧园，保留少量整块建筑、公园广场；建筑数量随用地变化，不固定为两栋或四栋。v8 将合并用地上的独立厂房、仓库改为沿道路方向的规整矩形主体，地块边界上的碎小台阶不再直接成为墙体。内部补路与向外扩张采用不同门槛，真实住房/岗位缺口可继续触发开发。旧存档已有建筑保持原状，新建及重新开发使用新规则；查看新版整体形态请打开复杂路网案例或从空路网重新生长。

城市内滚轮缩放，空格拖动或使用平移工具。Esc 取消当前绘制，Enter 提交。撤销与重做适用于暂停时的建设编辑，推进月份后清空编辑历史。保存包含地形、随机状态、城市状态和交通运行状态；地形起点与自动存档按地图隔离保存，手动存档仅在明确选择覆盖时替换。所有存档位于 `~/.shanhai/saves`，可用 `SHANHAI_DATA_DIR` 更改目录。

完整规则、机制和能力边界见 [项目文档索引](../docs/README.md)。其中 [功能规则](../docs/city-simulation-requirements.md) 定义产品目标，[系统架构](../docs/city-implementation.md) 说明执行流程，[城市生长](../docs/city-growth.md) 解释土地与建筑，[实现状态](../docs/implementation-status.md) 明确已实现、简化与未完成能力。

## 道路连接与路口设施

同层相交道路自动连接，端点也可吸附到已有道路中段形成丁字路口。桥梁和隧道的中跨交叉保持分离，端点接入可形成连接。编辑、删除、撤销和读取存档后会重新生成路网及路口。

放大地图后可查看车道方向箭头、车道分隔线、停止线、斑马线和信号灯标识。转向箭头按实际出口及单向通行方向生成。地面普通道路路口提供人行横道，主路交叉提供信号灯；高速、快速路及桥隧接入口不自动设置人行横道。距离过近的路口会省略放不下的标线。

模型 10 已接入按秒推进的信号控制与车辆排队。点击顶部「开始模拟」，车辆遵守停止线，红灯排队、绿灯放行，黄灯禁止新车进入；每个进口采用保护放行阶段，并设置全红清空与独立行人阶段。已进入路口的车辆先清空，冲突方向才能进入。

「模拟速度」滑块从实时、2×、3×、5×、15×、60× 逐级提高到每秒推进 5 分钟、1 小时、6 小时、1 天、7 天及 30 天。车辆、行人、信号灯和城市日历按模拟速度推进。光照在低于 1 天/秒时跟随模拟倍速，达到或超过 1 天/秒时改为实时推进，切换速度不会跳变当前光照时刻。高速采用交通活动抽样，跨月完整执行城市结算。暂停、恢复和存档会保留实景时钟及车辆状态。绿灯、黄灯与全红时长可在「信号配时」调整；道路编辑或配时变更后重新生成实景。

「城市交通分配」使用月度路段流量作为实景需求来源；空城市不会自动出现车辆。「验证人车流」用于检查路口放行和排队，示例人车不额外增加居民。城市发展与实景共享时间，在实际日历跨月时自动结算。信号期望等待及绿灯有效容量已接入机动车寻路与交通分配。实景采用简化跟驰和行人步行模型，未包含精细换道或每位居民的完整出行链。完整说明见 [时间与实景交通](../docs/simulation-and-traffic.md)。

## 建筑翻新与片区更新（模型 9）

默认开启「随模拟自动评估翻新与重建」，同时保留手动立项。系统每 6 个月比较建筑状况、持续空置、目标用途需求和保留旧楼的收益：状况较差且仍有使用者的楼可翻新，单栋可原址转换用途；街区至少 3 栋且持续空置面积达到 60% 时才评估整体拆除重建。默认普通更新最低楼龄 120 个月，持续空置 24 个月可提前评估；同址完成或取消后冷却 120 个月。自动投资每次不超过现有资金的 20%，同时最多 2 个进行中的更新项目，且不允许强制住户迁出。规划不能明显超过对应用途需求，替换建筑还须通过增量租金收益评估。阈值可在模型校准中调整，项目详情展示自动发起原因。停止新开发与迁入也暂停自动立项，已承诺的施工继续推进。

自动评估开启时，长期空置建筑保留到可行更新方案成立，不再到期直接清空；关闭自动评估会恢复旧版长期空置清空再开发逻辑。自动更新目前同样按市政投资模型记账，收益仅用于方案评估，不是独立开发商现金流或现实投资预测。

选择建筑后，可以分别执行「翻新建筑」「原址重建」「街区拆除重建」：

- **翻新**保留建筑身份、轮廓、用途与容量，下一月开工，施工 3 个月后恢复建筑状况。使用中的建筑每月状况下降 0.08，最低 20；状况对目标租金产生有限影响。年龄不重置，现有使用者继续使用。
- **原址重建**保留地块编号、边界和旧楼占地轮廓，拆除后生成新的建筑身份。可改变用途及楼层；旧容量在开工时退出，新容量交付后才可使用。
- **街区拆除重建**允许合并相邻土地、重新布置多栋建筑及共享广场。支持商业中心、住宅社区、办公园区、产业园区、仓储园区和混合街区；商业中心也可再次更新为住宅等用途。一个项目由多栋单一用途建筑组成，暂不模拟同一栋楼内的垂直混合用途。

「建设 → 街区更新 → 选择更新地块」可以点选范围。选择一块时扩展为其所在的闭合街区；选择多块时只更新所选地块，要求它们处于同一闭合街区。每次 2–100 块、最多 25 公顷。已有道路、公共空间、保护用地保留；首版不自动拆改街道，也不整合跨街区用地。

配置目标用途、主用途用地比例、楼层、建筑覆盖率、容积率及 1–4 期施工，点击「生成方案预览」，查看真实轮廓、保留范围、实际用途面积、住房/岗位容量、投资和最低工期后立项。用地比例是布局偏好，实际面积以预览为准；原址重建使用所选组合的主用途，保持原有占地，不应用覆盖率缩减。状态变化后旧预览失效，需重新预览。

项目下一月开始评估首期。每期先寻找可负担的城内住房；安置不足时等待，不扣款、不拆除。勾选「允许剩余住户迁出城市」后才可将无法安置的住户计为迁出。企业优先迁至同用途、容量足够的空闲建筑，没有替代空间时关闭并重新匹配就业。暂不包含临时住房、原住户回迁优先权或企业补偿谈判。

每期开工由市政承担预览中的建设、拆除和安置费用；开启预算约束后资金不足则等待。重建包含 2 个月拆除准备和按楼层计算的施工期，分期间隔至少 1 个月。可以要求每期至少出现 20% 的目标容量需求再开工。已交付部分先使用；未开工部分保留原楼，但不再接纳新住户。规划供应计入自动开发判断，交付不会直接创造人口、企业或就业。项目进度显示等待原因、投入、安置和实际运营，未处于拆除/施工阶段时可取消尚未开工部分。

项目、分期、规划几何及资金记录进入存档、独立方案和更新统计。旧存档升级到模型 9 后保留既有几何；立项/取消可在推进月份前撤销，推进后按原有规则清除编辑历史。正在更新的地块及其服务道路禁止直接删除或改用途，避免破坏在建方案。

## 启动

需要 Node.js 22+ 和 Python 3.11+。

```bash
npm install
npm run setup:electron
npm run setup:python
npm start
```

macOS / Linux 使用项目内 `.venv/bin/python`。Windows 请改为：

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm install
npm run setup:electron
npm start
```

安装依赖后，可运行 `npm start`，或在 macOS 双击 `启动山海.command`。

如果 Electron 二进制下载缓慢，可运行 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run setup:electron`，下载会按照 Electron 包内的 SHA-256 校验。

也可以使用环境变量 `TERRAIN_PYTHON` 指定已安装 NumPy 和 Shapely 的 Python 可执行文件。

## 操作

- 七种地貌：海岛、海湾、山脉、群岛、沙漠、丘陵、冻原。
- 地图范围支持自定义宽 × 高（1–1000 km，长宽比 1:8–8:1），输出像素按比例分配，比例尺显示真实 km / m。
- 地形起伏、平整度、海平面、地表细节、环境湿度修改后自动重新生成。「平整度」0–100% 平滑局部起伏并降低坡度，在湖泊和河流计算之前生效；0 保留原始地表。地形起伏控制整体高差。
- 水系支持河流密度（0 可关闭）、河道宽度（10–500 m）、湖泊数量（0–12）、湖泊目标直径（0.2–10 km）。湖泊会根据可用陆地放置，实际数量显示在地图下方。
- 海湾结构随种子随机组合：朝向、湾口宽度、内湾深浅与宽度、支湾、半岛、岛屿、山地与平原分布分别变化，不从固定城市模板中抽取。无需额外选择海湾类型。
- 「河口冲积发育」控制海湾低地向海扩展。当前区域模型不强制生成分汊；旧版 API 仍保留分汊模型。主要低地河流通过区域边界来水进入，同支流共用一个地形汇流图，流向海面或下游水体。
- 河网按汇流图共享下游河段，每段只生成一次。汇流网格检查整格内已有河流，细河道不会因采样遗漏而被支流穿过；接入点落在实际水面。短小支流按独立长度过滤，曲线平滑限制在原河谷网格附近，减少并行重叠和多余交叉。
- 干流不使用预画样条或等宽河谷压槽。河床深度、河岸坡度按米换算，提升输出分辨率不会加深河床；这仍是简化水系生成，不是流体动力学求解。
- 湖泊按周边最低溢流路径与湖面高差连接下游；高围堰的封闭湖盆保留。湿润环境允许浅出口冲切。这是简化判定，没有降雨水量平衡和地下水模拟。
- 最长边支持 768 / 1024 / 1536 / 2048 / 4096 像素；高程在所选精度直接生成，PNG 导出保留全部像素。4K 运算和内存开销较大。范围信息悬浮提示显示每像素的米数。
- 编辑种子或按 Enter 使用当前种子重新生成；「生成新世界」和种子旁的随机按钮使用新种子。
- 相同种子、地貌、参数与分辨率可复现相同地图。分辨率改变采样网格，视觉上保持同一地形，但逐像素结果不同。
- 默认「矢量地图」：海岸、河湖水面与分层高程以矢量路径重绘，缩放 1–32 倍仍保持边缘清晰；可切换自然地貌或高程视图。海岸与湖岸提取为简化曲线；河流直接由连续中心线和逐段宽度构建贝塞尔河岸，不描摹像素河床，河口按原始海岸裁切。放大不会增加原始地形数据的精度。自然地貌的阴影纹理仍为栅格底图。
- 左下角距离标尺随缩放自动选择 1 / 2 / 5 系列刻度并切换 m / km。右上角尺子按钮开启两点测距，依次点击起点、终点；再次点击重新测量，Esc 退出。测量以地图宽高的真实公里范围计算，缩放和平移不会改变距离。
- 等高线、坐标网格、全屏。等高线间距在图例中显示。
- 滚轮缩放，拖动平移；聚焦画布后方向键平移，`+` / `-` 缩放，`0` 回到默认视图。
- PNG 导出完整地图，不受当前缩放或窗口裁剪影响；保留当前视图、等高线、网格和测距，并绘制与导出尺寸对应的距离标尺。
- 参数自动存储于本机；再次启动恢复上次设置。

地图是程序化的虚构地形。窄河道保持最小可见宽度；干流随汇水面积逐渐加宽，河床与河岸写入高度场；湖泊目标直径在小范围地图上自动缩小。显示海拔为地面米值减去海面米值，不对应真实地理位置。比例尺按输入的地理范围换算。河流通过洼地填充和汇流累积生成连续支流与干流，流向海面或地图边界；河流可以流入湖泊。沙漠默认关闭河流，但可手动开启。算法未模拟完整的水文侵蚀过程。

海湾结构参考 NASA 的[旧金山湾影像](https://science.nasa.gov/earth/earth-observatory/san-francisco-bay-2474/)、日本国土地理院的[关东数字高程地形图](https://web1.gsi.go.jp/kankyochiri/degitalelevationmap_kanto.html)、香港土木工程拓展署的[构造与地形资料](https://hkss.cedd.gov.hk/hkss/en/publications-and-resources/educational-materials/hong-kong-geology/chapter-7/index.html)、新南威尔士州的[悉尼港流域地图](https://www.environment.nsw.gov.au/ieo/SydneyHarbour/maplg.htm)、NASA 的[里约影像](https://science.nasa.gov/earth/earth-observatory/popcorn-clouds-over-rio-de-janeiro-146728/)和[温哥华—菲沙河三角洲影像说明](https://eol.jsc.nasa.gov/Collections/EarthFromSpace/photoinfo.pl?PHOTO=STS085-715-33)。这些资料用于提取地貌关系，程序没有导入真实城市 DEM、建筑或道路；不代表真实城市复原，也不是潮汐、波浪、泥沙的数值模拟。

城市规划复用 API 返回的 `grid` 元数据与高度、水面、沉积栅格。新地图使用 `heightEncoding: "float32-le-meters"`：`elevation` 和 `water` 均为逐行排列、Base64 编码的小端 32 位浮点米值。高度相对于固定本地基准面，海面由 `grid.seaLevelMeters` 单独指定，显示海拔为 `elevation - seaLevelMeters`；负高程、超过 7200 米的高程都能直接保存，生成和水文计算不再为存储而截断或压缩高度。无内陆水面的格子在 `water` 中编码为负无穷，不能用 0 代替（0 米可以是真实水面）。河道的 `levels` 同样以米表示，`points` 仍为归一化平面坐标，`widths` 仍为源栅格像素宽度。

本版本只读取米制高度格式，不兼容旧版 uint16 地图；旧文件不会自动删除或改写，需要重新生成地图。高度和水面原始栅格占用为旧格式的两倍，4K 地图导入与存档解压上限同步提高至 350 MB。

`waterBodies` 提供河床下切前的海洋、湖泊位掩码（Base64，逐行、每字节高位优先、尾部补零），用于将连续河道几何与接收水体衔接。噪声的无量纲幅值只在地形合成结束时换算一次为米，此后的平整、水文、坡度、等高线和城市查询直接使用米值。海平面百分比仍是生成参数，不是存储单位。这是本地虚构坐标系，没有真实地理 CRS；地块几何采用独立米制向量，不把地形像素当作建筑。

Electron 启动时自动选择空闲端口，通过每次启动随机生成的令牌调用后端。渲染进程启用隔离与沙箱；关闭最后一个窗口时停止后端。浏览器预览不携带令牌，仅接受同源请求。

API 的 `bayStyle` 默认为 `random`，界面始终使用随机组合模式，旧的城市类型偏好不再生效。显式指定 `gulf`、`tokyo`、`san_francisco`、`hong_kong`、`sydney`、`rio`、`vancouver` 仍可调用旧模型，以兼容历史参数。海平面极端取值可能淹没湾口、平原或使海湾退化，这是水位改变地貌的结果。

当前交付为可直接运行的源码项目，尚未打包为独立安装程序；安装包需要额外打包 Python 运行时。

界面流程与存档专项检查：`npm run test:workflow`。

显示模式分为「精细视图」和「地图视图」。缩小地图自动切换为浅色制图样式，放大恢复建筑材质与实景细节；手动选择地图视图后可保持该样式。观察面板的光照滑块只调整光照，不修改城市日期。

地图制图样式采用暖白陆地、浅蓝水域、淡绿公园、灰白分级道路与低对比建筑轮廓。路名沿道路方向排布，并按可视长度、曲率和屏幕碰撞筛选；城区、地点和道路共享标注避让。地点使用本地分类图标，支持点击名称选中设施。缩小时隐藏普通庭院标注，保留重要公共设施。图标来源与许可见 `THIRD_PARTY_NOTICES.md`。

可选视觉回归：在安装 Playwright 浏览器和 Python 依赖的开发环境中运行 `node scripts/check-map-style.cjs`。该检查导入既有街区样本，验证标签碰撞、地点点击与全屏退出后的地图中心，并输出近景、远景和窄窗口截图。可用 `MAP_PYTHON`、`MAP_CHROMIUM` 指定运行时。

### 区域与地名

先根据地形生成稳定的地名区域，再命名区域内的道路、商店、住宅、公共设施、街坊和站点。城区和街坊优先使用两字地名主体，重名时另选简短地名，必要时扩展为三字；不再把区域词根与另一个两字词强制拼成四字。建筑、道路和设施仍将区域关联与独立名称主体混合使用，例如「清川片区」可以出现「清川文华路」「清悦汇商厦」「嘉集百货」等名称。部分名称保留完整区域词根，部分借用其中一个字，其他使用独立店名或楼名；区域归属始终通过 nameRegion 保存。重名时重新组合名称主体，词库不足时扩展汉字组合，不再用数字编号区分建筑。地名区域独立于经济活动识别的城区：水面、河道及超过 25% 的陡坡优先隔开区域，连通陆地采用坡度加权距离划分，大面积平地以约 1.2 公里的覆盖距离自动细分。分区采用最多 96×96 的分析网格，连接边额外采样原始高程并检查河道，以减少漏过窄河的问题；这是地形启发式分区，不是精确流域识别。道路按路线长度中点归属，建筑按地块中心、设施和站点按位置归属。区域和名称保存到存档，不随后续道路建设重新划分。

名称使用独立于经济模拟的随机源，以地图种子和对象身份确定；新生成名称会避开已有名称。旧版自动命名的道路、建筑、设施、站点和街坊会一次性升级为多样化名称，之后保持稳定；已有自动名称与其他地点完全重名时会重新生成，火车站设施与其专属站点共享名称的规则保留。旧版自动生成的四字城区和街坊地名会缩短一次，保留原来的前两字并检查重名；城区分裂合并前先迁移旧名称，保证继承稳定。手动名称保留。无空间位置的运营线路仍按类型独立取名。城区扩张、合并时优先延续原名，分裂时较大的存续部分继承原名，其他部分另取新名。功能类别和中心等级独立于名称保存。

地图近景显示建筑名称，远景按优先级保留道路、城区和重要地点，继续使用屏幕避让。详情面板、对象选择器与精细视图也显示实际名称。新建特殊建筑、站点和线路的名称输入框留空即可随机命名。

命名回归：`python -m unittest tests.test_naming -v`，覆盖地形阻隔、平地细分、区域关联、简短城区与街坊名称、旧四字地名迁移和继承、密集建筑名称多样性、无数字编号、重名修复、旧名称升级、同种子复现、不同种子差异、2000 条道路去重、独立随机源、旧存档升级、保存重载、撤销重做、预览不占用名称以及城区继承。

### 铁路与地铁互通

铁路与地铁采用统一的 1.435 米轨距和双线中心间距。精细视图按实际曲线铺设钢轨、混凝土轨枕和扣件；铁路显示碎石道床，地铁显示混凝土板缝、检修边道和电缆槽。细节按缩放级别控制，纹理使用确定性程序绘制。

两类轨道可磁力吸附连接，同层交叉共享节点；跨层接入须显式确认，未接入的立体交叉保持独立。火车和地铁线路可以使用混合轨道及两类客运站，车速仍受车辆和路段限速约束。有轨电车和汽车网络独立。地下轨道采用检视剖面表达，当前未新增列车实体动画或铁路道岔信号联锁。

轨道回归：`npm run test:rail`。浏览器实测：`npm run test:rail:visual`，可用 `CHROMIUM_EXECUTABLE` 指定 Chromium。

### 连续车辆旅程

正常车流采用城市交通分配中的真实起终点，从地块或设施的道路入口出发，到目标入口减速停车。同一车辆沿完整有向路线跨越多个路段与路口，支持单条道路上的直接出行。没有城市出行记录的旧存档仅使用路网端点的已有交通量，验证模式另提供明确的测试车流。

车辆使用连续车道路径和相切转弯曲线，提前减速、平滑加速，并按实际路径距离保持跟车间隔。红灯停车位置包含车头长度和安全余量；前方道路堵塞或仍有行人过街时，不驶入路口。抵达目的地后短暂停留再结束显示。交通旅程不会新增居民或改变月度经济账目。

后端每 0.05 秒生成权威轨迹，前端按动画帧播放轨迹及对应灯色，网络延迟时停留在已知安全位置。静态建筑的颜色、深度与环境遮蔽缓存复用，车辆仍受建筑遮挡。实时至 5 倍时交通同步加速，更高速度保持最多 5 倍的交通样本，城市日历与光照规则独立保持原有推进方式。道路没有变化的跨月结算保留在途车辆、信号相位与路口占用。

专项回归：`npm run test:traffic`。浏览器动态验证：`npm run test:traffic:visual`，依赖 Playwright，可用 `CHROMIUM_EXECUTABLE` 指定浏览器。测试截图及运动记录默认写入忽略目录 `test-results/vehicle-motion/`。
