# 山海项目文档

山海是本地运行的地形生成与城市规划模拟工作台。用户创建世界、建设交通和公共设施，再观察人口、就业、土地市场、建筑与城区如何相互影响。项目需要同时满足可玩、规则一致和结果可解释三个目标。

本目录描述整个项目要实现什么、各系统遵循什么规则、代码如何执行这些规则，以及目前实现到了什么程度。需求规定目标；专题说明当前机制；实现状态明确简化和缺口。这里不按提交、版本或修订轮次编写内容。

## 共用概念

- 世界是固定的地形与空间范围；城市是依附世界的建设、人口、经济与历史状态。
- 地块是土地单元，建筑是地块上的实体；建筑容量、实际入住和就业分别记录。
- 街区是道路围合的物理空间；城区是从实际用途和活动中识别的功能区域。
- 交通基础设施提供通行条件；线路提供运营服务；出行是包含接驳和换乘的一次完整活动。
- 月度交通描述代表日需求与分配；画面中的人车是活动样本。
- 需求是目标行为；当前实现是代码行为；历史实验是特定条件下的观察结果。

## 全项目必须保持的约束

1. 所有对象使用米制世界坐标。视口、缩放、像素密度和材质不能改变长度、面积或经济结果。
2. 地块、道路、公共设施和建筑占有真实空间；不能通过视觉覆盖绕过地形及土地冲突。
3. 家庭、岗位和住房分别计数。新建住房不自动造人，新增岗位不等于实际就业。
4. 出行必须走真实允许的网络。没有接入、没有运营或容量耗尽时应产生相应失败结果。
5. 需求、供应、价格和开发形成有惯性的反馈；不能因为建设站点就固定涨价或必然出现高楼。
6. Python 城市状态是计算依据。界面、专题、详情、历史与导出使用相同口径。
7. 同模型、相同初态和输入在约定容差内可复现；随机状态与运行态必须随存档保存。
8. 设计目标、简化模型、画面表达和未完成能力必须明确区分。

## 当前实现的定位

当前代码已包含地形生成、交通编辑、多方式代表日出行、家庭与行业群组、土地市场、自动生长、设施、城市更新、统一时间、实景信号人车、统计、存档及方案比较。当前城市模型标识为 `shanhai-city-11`，校准标识为 `urban-10`。

这些能力共同形成城市玩法闭环，仍然使用家庭代表劳动者、简化企业、有限轮交通分配和环境代理指数。大城市性能、旧地形兼容、精细公交排队、能源水务网络、航运航空等边界见实现状态文档。

## 资料组织与维护

`docs/` 只存项目说明。内置案例存档在根目录 `examples/`；测试及视觉检查输入在 `city-planner/tests/fixtures/`；截图由脚本生成到根目录 `images/` 并由 Git 忽略；实验报告、日志、历史场景和测量在根目录 `experiments/`；应用运行材质在 `city-planner/renderer/assets/`。应用内置案例和固定测试输入不再依赖实验目录。

规则变化时更新所属专题、需求和实现状态；默认值变化时同步参数目录。文档应解释最终规则、触发条件、状态变化、失败行为和简化范围，不追加按修订轮次组织的过程说明或测试通过数量。行为验收场景用于定义预期，测试输出留在测试工具和实验资料中。
