# 世界、地形与建设条件

## 1 世界的职责

世界为城市提供固定的米制空间、高程、水体和自然建设条件。地形影响接入成本、速度、土地适宜性和景观；它不能只作为背景图片。用户开始建设后，世界数据随城市固定，改变视图不会重新生成世界。

当前生成器支持海岛、海湾、山脉、沙漠、丘陵、群岛和冻原。种子与参数控制结果；海湾另有结构选项。核心实现为 [terrain.py](../city-planner/backend/terrain.py)、[hydrology.py](../city-planner/backend/hydrology.py)、[coastal.py](../city-planner/backend/coastal.py) 和 [startup_land.py](../city-planner/backend/startup_land.py)。

## 2 生成参数与空间分辨率

| 参数 | 作用与约束 |
| --- | --- |
| 种子 | 1–80 字符，控制可复现的程序化生成 |
| 地貌 | 七种预设之一，决定总体地形组织 |
| 栅格分辨率 | 768、1024、1536、2048 或 4096；影响采样与生成成本 |
| 世界宽、高 | 各 1–1000 km，长宽比限制在 1:8 至 8:1 |
| 海平面控制 | 生成参数范围 15–70；当前换算为固定基准上的米制水面 |
| 高程与粗糙度 | 控制整体起伏和局部变化 |
| 平整度 | 平滑局部坡度并保留海岸约束 |
| 湿度、河流密度及宽度 | 控制排水与河道形态 |
| 湖泊数量与尺度 | 0–12 个湖泊，数量必须是整数 |
| 河口三角洲 | 控制河口及岸线的生成特征 |

世界范围与栅格分辨率是独立参数。固定分辨率下扩大范围会降低每米的采样密度，不能因为图像可放大就认为地基数据更精细。地图最大范围表示输入上限，不是可支持同等规模城市的保证。

## 3 坐标与高度契约

### 3.1 平面坐标

城市对象使用 `[x, y]` 世界米制坐标。原点位于地图左上，x 向右、y 向下。道路长度、地块面积、步行距离、建设费用和速度均由世界几何计算，不能由屏幕像素计算。

前端将世界坐标转换成屏幕位置。平移、缩放、设备像素比和导出尺寸只改变表达；相同道路在任何视图下应保持相同长度和费用。

### 3.2 高度存储

当前 `heightEncoding` 必须为 `float32-le-meters`。地表和内陆水面使用小端 float32 网格，以 Base64 存储；海平面由 `grid.seaLevelMeters` 指定。陆地高程必须有限，无内陆水面的位置允许使用负无穷作为缺省标记。

高程以固定本地垂直基准保存，不能随海平面参数重新缩放。面板中的相对高程可以减去海平面，但存储高度仍是米值。格式由 [height_format.py](../city-planner/backend/height_format.py) 统一编解码。

### 3.3 旧数据边界

当前解码器拒绝缺失或不匹配的高度编码。城市对象迁移和地形格式兼容是两件事：旧模型标识被接受，不代表旧归一化高程或 uint16 地形可以直接读取。历史实验存档可能因此无法加载，应明确诊断，不能默默把旧数值当成米。

## 4 海洋、河流与湖泊

海洋根据地表相对海平面的关系识别；内陆水体同时使用水面高度和河道几何。道路与土地不能只检测中心点是否在水中，否则狭窄河流、湖岸和旋转地块会被漏过。

河道保存连续路径及宽度，在建设检查中缓冲为实际占地。渲染中的最小可见河宽只是显示策略，不决定物理宽度。湖泊具有各自水面，并通过水文处理形成出流条件。

水体检查优先于一般坡度失败：跨水路线应该提示选择桥隧或改线，而不是只显示河岸陡坡。桥隧使用独立结构条件，不能通过关闭水体绘制取得可建土地。

## 5 启动区域

所有新生成地貌确定一处启动区域，优先选择原有陆地中海拔适中且起伏较小的位置。常规地图提供约 600 × 600 m 的平缓核心；小地图按短边约 40% 缩小。核心外围平滑过渡，粗栅格还保留额外采样缓冲。

当高海平面使陆地不足时，生成器允许局部抬升形成启动台地。湖泊避开预留区域，穿越核心和过渡带的河道段不参与开挖，避免后续水系破坏启动空地。

`startupArea` 记录中心、可用边长和海拔。同种子及参数下保持可复现。空城初次进入规划时定位这里；已有路网则优先定位路网。此规则只作用于新世界，不修平已有存档。

## 6 地形采样与建设检查

[geometry.py](../city-planner/backend/city/geometry.py) 的 `Terrain` 负责统一读取世界、判断水体及计算坡度。高程采用双线性插值，坡度来自邻近采样差分。插值改善连续性，但不会增加原始采样信息。

地块检查包含边界、内部代表点及覆盖区域采样，不能只依赖包围盒网格。整个形体必须位于世界内，避开连续河道并满足用途的坡度条件。不同对象可使用不同合法阈值，不能将道路纵坡、地块平均坡度和最大坡度混用。

当前沿街开发采用最高 45% 的地形坡度限制。百分比表示高差/水平距离，45% 不等于 45°。超过阈值的既有空地在开发时继续被拦截。

## 7 道路工程与地形

道路按实际采样中心线测量长度、爬升及坡度。默认道路允许较宽松的游戏工程上限，普通道路纵坡上限约为 30° 对应的坡度比；铁路为 16%，其他轨道采用其类型阈值。这些参数是可玩性选择，不是现实工程规范。

地形影响自由流时间、步行耗时、有效容量、工程投资和维护。桥梁及隧道还计结构成本。预览与正式命令共用规则，失败返回可定位冲突点。

地面道路因坡度不合法时，`road_alignment.py` 可在有界范围内搜索局部绕行和折返，保留用户控制点并重新校验每段。搜索受访问数、长度和控制点数限制；找不到合法线路就返回失败，不放宽地形或占地规则。

## 8 地块地形摘要

每块土地保存高程、平均和最大坡度、局部高差、邻水条件、景观、低地邻水指标、工程倍率和强度限制等摘要。开发、地价和观察界面读取相同摘要。

| 因素 | 参与的规则 |
| --- | --- |
| 坡度与高差 | 建筑合法性、工程费用、楼层和占地限制 |
| 景观与邻水 | 住宅吸引力、土地估值和公共空间选择 |
| 低地邻水 | 土地负面贡献及工程条件代理 |
| 道路高差与水体阻隔 | 通勤、货运和设施接入，再反馈到开发 |
| 自然边界 | 地块裁剪、公共空间和自动路径合法性 |

低地指标不是洪水发生概率，污染与噪声也不是物理浓度。这些值只能按游戏指数解释。

## 9 山地空城的开发规则

平均坡度超过 20% 的候选新建筑最多 3 层、占地最多 240 m²。小型坡地住宅以局部阶梯基础估算额外工程成本；启动人口不足 100 人时住宅收益评估期限放宽，并优先评估少量坡地住宅。

基础公园达到约 40 人、街角广场达到约 20 岗位后才开始考虑。人口不足 100 人时为住宅保留最多三个较平缓的空地，减少配套抢先占满启动土地。已建配套不会为这一保留策略自动拆除。

这些机制降低空城启动困难，仍需实际合法土地、可行收益与住房就业条件。不能保证任意手绘线路在任意山地都能成功发展。

## 10 尚未覆盖的世界能力

当前建设期间不提供局部挖填地形编辑器，不执行物理洪水或侵蚀时间演化，不导入真实 GIS 坐标系。世界采用虚构本地米制坐标，适用于玩法探索。地形之后的人工修改若要加入，需同时处理道路、建筑、水体和存档一致性。
