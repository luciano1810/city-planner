# 行人实景

选择「加载地图 → 城市案例 → 打开实景街区」，点击顶部唯一的「开始模拟」。人车、日照和城市发展共用速度滑块；默认暂停。调整当天时刻会暂停模拟，保留人车当前位置。详见 [统一模拟](unified-simulation.md)。

行人使用真实比例的三维头部、躯干、手臂和腿部。16 套固定外观由服装贴图、裤装、肤色、发色、鞋子、帽子与背包组合形成，身高为 1.60–1.83 米。步态由实际走过的距离驱动，站立等待时停止摆臂和迈步。精细实景中的人物参与深度遮挡、太阳阴影和接触阴影，夜间接受现有场景的环境着色与灯光叠加。流畅实景与简洁地图使用相同服装图集绘制俯视人物。

步行网络按地面可步行道路的两侧人行道构造，曲线路段连续采样，转角连接避开车行道与建筑。信号路口的斑马线位置、宽度与显示层采用相同的路口净距规则。过街前检查行人绿灯、剩余过街时间及车辆清空状态，已进入斑马线的行人继续走到对侧。车辆同时检查过街占用，避免与未完成过街的人冲突。无独立信号控制的路口不会产生未经保护的过街动作；快速路、高速公路、桥梁与隧道不布置本轮实景行人。

同向行人保持间距，双向步行流在中心线两侧错开。行人、车辆、信号灯、昼夜和月度发展共享模拟速度。实时至 60× 使用精细人车步进；更高速度以抽样显示交通，跨月执行完整城市结算。暂停同时固定位置和步态，重置人车流会重置行人。存档包含路线段、距离、步态、等待和累计过街状态，导入后确定性续行；旧存档没有行人字段时补建行人。

这些人物是显示层的交通活动抽样，不额外增加居民或改变月度经济。城市交通分配模式按已有住户数量抽样，空城不会凭空出现人；验证人车流模式最多布置 180 位行人。当前路径选择是确定性的街区步行流，不映射到每位居民的完整通勤链。

## 相邻路口修复

旧车辆逻辑会把上一个路口的通行预留当成下一个路口也已获准通行。相邻路口较近时，这可能跳过下一个红灯检查。现在每个目标路口单独检查许可，多个相邻路口的占用分别保留，沿完整后续路线累计清空距离后逐个释放。旧格式的单路口占用存档仍可读取。

## 代码和资源

- `city-planner/backend/city/pedestrians.py`：步行网络、排队、过街、状态校验和存档。
- `city-planner/backend/city/signals.py`：共享时钟、人车互斥、连续路口占用。
- `city-planner/renderer/pedestrian-renderer.js`：16 套外观、三维步态和 Canvas 兼容绘制。
- `city-planner/renderer/assets/pedestrian-clothing.png`：16 格服装材质，由内置 ImageGen 生成，本地加载。
- `city-planner/tests/test_pedestrians.py`、`city-planner/tests/pedestrian-renderer.test.cjs`：行为、存档、相邻路口及几何回归。

本轮运行 36 项 Python 测试、24 项 JavaScript 测试，全部通过。实际 Chromium 界面验证了贴图加载、180 人活动、启动与暂停、60× 加速、夜景切换、三种品质、导出行人状态及原有建筑数据保持。浏览器无脚本错误。检查记录见 `experiments/pedestrians-browser-evidence.json`。

人物服装图集的生成方式与提示词见 `city-planner/renderer/assets/README.md`。
