# 地铁火车系统重构需求与开发提示词

请重构山海游戏中的地铁与火车系统，使其具备完整的车站建设、轨道连接、线路运营、共线调度、直通、换乘、客流管理和城市发展反馈。火车与地铁在同一页面统一管理，并延续公交系统已经要求的菜单风格、线路管理和真实操作流程。

本文可以整体交给开发代理执行。正文定义开发目标与验收条件，不表示这些功能已经实现。用户明确要求、补充设计及术语解释分别列明；发生范围冲突时，以最新用户要求为准。

## 1 范围和执行约束

本次重构的核心范围是地铁与客运火车。公交能力作为交互参照、接驳基础和回归验收基线。有轨电车保留菜单与缩略图要求，完整电车运营不作为本次必须新增的范围。货运铁路及现有其他交通能力应保持兼容。

早期“地铁和有轨电车先只做菜单与缩略图”的要求，已被后续地铁与火车完整功能要求更新：地铁和客运火车需要实现本文运营功能，有轨电车继续按原有范围处理。

开始开发前检查现有车站、轨道拓扑、公交管理、交通分配、车辆运行、时间推进、财政和存档实现。复用共同能力，保留工作区未提交及正在进行的改动，避免覆盖其他任务的成果。

经济结算应对齐游戏最新的每日 0 点结算机制，兼容尚在进行的相关改动。设置变更可以重新计算服务和需求，但不能触发额外财政结算，也不能恢复旧的周结算或月结算调度。

完成全部预期编辑并自查后，统一运行与改动相关的测试，再进行真实界面全流程实测。实现期间不要反复运行测试；确需诊断不确定行为时，先说明原因。默认不运行整个项目测试集。

## 2 用户要求与术语口径

| 表述 | 本文采用的含义 | 来源 |

| 月行线 | 按越行线理解，用于快车超过普通列车 | 对用户原词的解释 |

| 只连一边 | 按首末站不同的开放式线路理解，默认往返；单向运营另设选项 | 解释及补充设计 |
| 直通 | 同一列车沿轨道连续经过火车站与地铁站，乘客可留在车上 | 用户要求 |

## 3 菜单与公交回归基线

公共交通菜单保留“公交车、有轨电车、地铁／火车”三个分类，参考现有建造、区块等菜单的卡片、缩略图、选中状态、按钮和提示样式。桌面与窄屏均应可用，提供键盘操作、清晰焦点及可读的错误状态。

公交车分类需要保留三项操作：新建公交车线路、管理线路、建造公交车总站。新建线路以已建好且接入道路的总站为前提；允许在已有道路沿线任意合法位置选站，向两侧路边磁力吸附，按点击顺序沿实际道路连接。不能限定为路口或固定预设点。至少两个不同站点后可按 Enter 创建，提供 Backspace 撤回和 Esc 取消。

公交站点应位于路侧，车辆和线路路径遵循行驶侧与道路方向，往返方向按各自道路侧表达。显示几何、寻路和车辆运行使用一致的连接规则。

公交管理继续列出全部公交线路与乘坐人次，支持更换车辆、调整车辆数量、查看各站综合需求和时间变化、设置运营时间、修改线路名和颜色。此次铁路重构不得破坏这些能力。

有轨电车分类保留创建线路、新建有轨电车站、新建有轨电车轨道的菜单和缩略图。地铁／火车分类统一提供新建地铁站、新建火车站、建设兼容铁路轨道、新建线路、管理线路，以及道岔、折返设施和越行线建设入口。缩略图应区分层级、车站与轨道用途。

观察菜单提供「显示公共交通线路（公交 / 地铁 / 火车）」开关，控制地图上的运营线路叠加。开关只影响显示，保持建设草稿、实际车辆和运营数据独立，记住本机显示偏好。地图与精细视图、桌面与窄屏均可操作。

线路视觉参照苹果地图公共交通样式：真实地理路径、清晰的线路色与白色外描边、圆角转折、白心站点、简洁的线路名称标识，共线服务并排显示。站点和文字随缩放控制密度，不为美观改变实际轨道或公交行驶侧。此为用户补充要求；外观采用本项目绘制代码，不复用苹果地图素材。

## 4 统一对象与管理页面

火车和地铁使用统一页面、兼容轨道网络和共同运营逻辑。可以按地铁、火车、直通线路筛选，但不能拆成互不连通的管理系统。

实现时区分以下对象，保持各自稳定身份及连接关系：

- 车站：包含站厅、一个或多个站台及出入口。
- 站台：每个站台具有稳定编号、长度、层级及独立轨道接口；线路停站引用具体站台，不仅引用车站中心点。
- 轨道设施：包含区间、道岔、渡线、越行线、折返设施和层级转换。
- 线路服务：引用实际轨道和停站顺序，保存运行方向、车型、编组、配车及时间计划。
- 列车：按照线路和调度结果实际运行，具有容量与运行状态。
- 换乘连接：记录车站之间真实可行的步行路径。
- 换乘站组：汇总相连的子站，保留各站身份和数据。

基础设施、运营服务、步行接入和乘客旅程分别建模。新建线路不能复制基础设施容量；同一地下站的多个入口也不能生成多座独立车站。

## 5 车站层级与建设流程

点击“新建地铁站”后弹出高架、地下、地面选择菜单。三类地铁站均为必需能力。火车站沿用相同层级、接口和合法连接规则；为火车站提供相同三类建设配置属于补充设计。

选择位置后实时预览车站占地、站台、轨道接口、出入口、朝向和费用，并支持旋转。车站可以先建后接轨；轨道未接通时标记为待连接，不产生运营能力。

建设火车站或地铁站时，玩家可以选择站台数量。数量变化应同步改变占地、费用、站台布局和轨道接口预览。连接轨道时应吸附到具体站台的接口；新建线路时应能选择停靠的具体站台，并显示其连接状态和已服务线路，不能把多个站台折叠成一个无差别选点。

建成后仍可编辑站台数量。增加站台须重新校验空间、层级、入口及费用；减少站台须检查轨道连接、线路引用与列车占用，保留未删除站台的稳定身份。存在占用或引用冲突时说明涉及的站台和线路，保留编辑草稿，不得静默删除连接或将列车、乘客转移到不存在的站台。上述站台数量选择及建后编辑为用户补充要求。

选址与已有建筑重叠时，只允许地下建设。高架和地面选项禁用并说明原因，地下建设保留上方建筑及其居住、就业和经营状态。

检查地形、水域、地面占地、地下设施、轨道层级及必要净空。地面入口与地下主体分别校验。预览失败不能扣款或留下半成品对象；正式提交再次校验并原子完成建设。

## 6 建筑内部入口和室外入口

地下站位于已有建筑下方时，默认建立该建筑内部到站厅的连接通道。建筑内的居民、工作人员和访客可以直接进站。外部乘客通过建筑现有合法入口进入内部通道，建筑内部人员无需先走到室外入口绕行。

建设预览应列出关联建筑和连接位置。覆盖多栋建筑时明确实际连接哪些建筑，支持调整关联，不能因投影重叠而自动给所有建筑增加零距离接入。

同时在附近自动寻找合法空地，预览并配套建设一个室外地面入口及小型入口广场。该入口连接地下站厅与周边人行道，供周边乘客独立使用。玩家可以调整位置和朝向。

建筑内部入口、室外入口及连接通道纳入同一次建设预览和费用。附近没有合法空间时，提示调整站位或入口位置，保留可编辑草稿；确定合法室外入口后再完成初次建设。不得自动拆除原有建筑或把入口强行放入冲突空间。

入口、水平通道与楼梯、电梯等垂直连接应组成真实路径，计入步行和垂直交通时间。覆盖人口、岗位及需求根据实际连接更新。

车站编辑支持增加、移动、关闭和删除入口，并区分建筑内部入口、室外入口。显示入口关联建筑、通道长度、步行时间和使用状态。

建筑拆除或内部通道关闭后，仅使相应连接失效。室外入口仍有效时，车站可以继续接纳外部乘客。没有可用外部入口时，仍可保留合法站内换乘和列车通过能力；没有任何有效接入时不得虚构进出站客流。

## 7 轨道连接与多线路共线

轨道提供高架、地面、地下及合法层级转换，支持端点与车站接口吸附、路径预览、长度和费用提示。弯曲、坡度、净空与方向要求统一作为可配置模型规则。

同一段轨道、车站和站台可以服务多条线路。同层线路分支与汇合使用真实道岔；不同层级的投影交叉不能自动连通。不能通过一条显示线绕过断轨、方向或层级限制。

多线路共线时，统一计算区间、道岔和站台占用，以及列车安全间隔、排队、发车机会和延误。各线竞争同一份可用容量，不能让每条线分别获得整段轨道的全部容量。

显示共享区间、关联线路、计划班次、实际可提供班次及限制原因。减少某线班次或增加越行设施后的变化，应反映到整个共享网络。

提供地下视图或剖切显示，保证地下车站、轨道、接口和通道可选择、可编辑。显示路径与寻路使用一致拓扑；列车在实际股道上运行。

## 8 地铁火车直通与线路创建

火车站和地铁站能够通过兼容轨道直接连接。同一线路可以连续停靠两类车站，同一列车可以连续驶入这些车站，乘客可留在车上继续旅行。直通过程不增加换乘次数，不重复收费或重复计作一次进出站。

以游戏需要的互通能力为目标统一轨道、列车和站台兼容规则，默认普通配置能够直通。不同车型涉及编组长度、站台长度、限界、速度或其他限制时，明确展示并在创建线路前检查；不能仅凭“火车／地铁”标签拒绝已经兼容的运行路径。

已有轨道连通后，按顺序点击车站创建线路。选择至少两个不同站点后按 Enter 提交，Backspace 撤回，Esc 取消。预览停站顺序、途经区间、方向和预计运行时间。

多站台车站应提供具体站台选点或选择器，预览所选站台编号、可达轨道及其共享服务。线路保存站台引用，后续编辑停站顺序或站台数量时重新校验；同站换用其他站台必须有合法的轨道进路。

自动寻找合法轨道路径；存在多个选择时允许选择途经轨道或关键节点。断轨、方向错误、列车不兼容和站台不足应定位到具体区间或车站。

支持开放式往返线路、环线及单向线路。环线必须实际闭合，可以顺向、逆向或双向运营；开放式线路默认往返。单向线路必须具有合法车辆循环或回送方案，不能把列车瞬移到起点。

允许多条线路共用站点并采用不同停站方案。短线服务和选择部分区间运行属于补充能力，其终点同样受折返条件约束。

## 9 折返与列车安全

开放式往返线路两个末端都需要折返能力，通过折返站台、渡线或折返线实现。建设预览显示所需空间与连接；设施不足时阻止线路投入往返运营，并指出补建位置。

同一站可以是一条线路的终点和另一条线路的中间站。折返、停靠与通过列车共同接受站台和进路占用约束。

列车完成进站、上下客、停站、换向、等待和发车过程，遵守安全间隔、道岔及站台限制。拥堵时排队等待，提供可解释的阻塞原因和恢复机制，不能穿车、瞬移或永久死锁。

增减列车和更换车型时明确车辆投入与退出规则。优先在起点、终点或已有车辆段执行；载客列车完成必要行程后退出，不能删除车内乘客。若项目已有车辆段则接入，新增完整车辆段建设玩法作为补充设计，不额外改变用户要求的基本建线流程。

## 10 越行线与快线

提供越行线及具有越行能力的多股道车站建设，支持普通线路和快线。在线路管理中为各站设置停靠或通过，快车不停靠站点不得上下客。

跳站与超车分别处理。没有可用越行条件时，快车应跟随前方慢车；具备越行轨道、安全进路和空闲资源时才能超过慢车。

越行调度考虑站台、道岔、对向列车及共享区间冲突。明确优先级和等待规则，避免普通列车长期得不到放行。

快线实际收益由停站方案、轨道条件、候车时间和拥堵共同决定，不固定赋予速度加成。乘客按照完整旅程成本选择普通线或快线。

## 11 邻近车站自动换乘

邻近车站具备合法步行路径时自动形成换乘关系，适用于地铁与地铁、火车与火车、火车与地铁以及不同层级车站，无需玩家手动创建换乘线路。

使用实际可通行步行距离和换乘时间判断。距离阈值作为公开配置项；建议初始值为 300 米实际步行距离，由游戏地图尺度校准并在交付说明列明，该数值属于补充默认值。

自动寻找已有站内通道、出入口、人行道和合法过街设施。不同层级需要楼梯、电梯或连接通道，并计入时间。已有路径有效时直接建立关系；缺少必要工程时生成合法通道的预览和费用提示，工程形成有效连接后开放换乘。

被河流、封闭道路、无通道建筑等障碍隔开的邻近车站，显示“邻近但尚未连通”及原因，不能靠直线距离制造通道或零成本换乘。

地图与统一管理页自动展示换乘站组。保留每个子站的身份、名称、站台、出入口和线路，显示换乘距离、路径、时间与状态。同一站的多个入口不另算换乘站。

站组内部寻路仍经过真实连接边。例如 A 能步行到 B、B 能步行到 C，不能因同属一组让 A 直接零时间到达 C。汇总指标按实际乘客事件去重。

新增、移动、删除车站及出入口，关闭通道或改变过街条件后，自动重新检查连接和站组。公交接驳使用同一套合法步行网络。

## 12 统一线路管理

列表展示全部地铁、火车和直通线路，包括停运、待连接和故障线路。显示名称、颜色、类型、服务状态、站点数、列车数量、班距及乘坐人次，并可按类型和状态筛选。

设置界面保持简洁：默认展示名称、车型、编组、配车方式与运营时段；停站和站台、高级运行参数、客流统计及共享限制按需展开。自动配车显示目标班距，指定配车显示列车数量；首末班使用时间选择器，跨午夜明确标注次日，全天运营提供独立开关。建站的尺寸与朝向、车站的接口坐标和详细统计折叠显示，站台数量始终可直接编辑。此为用户补充的界面简化要求。

点击线路后可以完成以下操作：

- 修改名称和颜色，更新列表、线路图及相关车辆显示。
- 更换车型、调整编组与单列容量，检查站台及全程轨道兼容性。
- 调整投入运营的列车数量；选择按目标班距自动配车，或按指定数量计算可提供班距。
- 设置首班、末班、全天或跨午夜运营时间。
- 编辑停站顺序、普通或快线停站方案、方向、途经区间及短线范围。
- 查看各站综合需求、分方向需求、小时变化及历史趋势。
- 查看共享区间、共线服务、拥堵瓶颈、延误及未满足需求。
- 暂停、恢复或删除线路。

以上设置必须影响列车运行、运力、候车、费用和乘客选择。运营时段结束后停止新发车，已经发出的列车完成其合法行程；跨午夜服务不能在日期切换时被错误清空。

末班截止时刻与每日 0 点结算是两个独立条件。例如 23:30 至次日 01:30 的线路，在 00:00 归档和结算后继续正常发车，到 01:30 才停止新发车；已发列车继续完成行程。

保存前展示不兼容项，校验失败保留草稿且不部分修改运营状态。切换线路或刷新数据时保留未保存的编辑内容。停运线路保持可查看、可编辑和可恢复。

## 13 车站需求与客流统计

点击车站或换乘站组显示名称、层级、状态、站台、服务线路、出入口和换乘通道。点击编辑可改站名及管理周边入口。

车站编辑同时提供站台数量调整，逐站台显示轨道接口、连接状态、线路引用和当前占用；平台扩建或缩减按第 5 节的原子校验规则提交。

核心需求指标至少包括：

- 当前候车人数及等待时间。
- 进出站、上下车和换乘人次。
- 各线路、各方向的需求、实际承接量和未能上车等未满足需求。
- 周边通过实际入口可达的人口、岗位及主要出行目的地。
- 小时需求变化及按模拟日期记录的历史趋势。

建立所需核心事件和数据链路。当前候车、进出站、上下车和换乘数据不能从车辆动画或固定比例倒推。站内总人数等扩展指标若未模拟，应标明未模拟，不能显示为真实人数或用零代替未知。

统一采用以下统计口径：

| 指标 | 计数规则 |
| --- | --- |
| 当前人数 | 当前模拟时刻实际保留的候车或乘车状态人数 |
| 上下车人次 | 每次登乘或离开一列车分别计数，往返分别发生 |
| 进出站人次 | 穿越车站外部接入边界的事件，站内换乘不再计外部进出站 |
| 换乘人次 | 下车后接续另一运营服务，包含实际换乘步行和再次候车 |
| 直通经过 | 留在同一列车继续旅行，不新增换乘或上下车事件 |
| 实际承接需求 | 已被服务的乘客事件或旅程，标明时间范围 |
| 未满足需求 | 实际尝试出行后因运力、班次或连接等条件未完成的需求，标明原因 |
| 潜在需求 | 根据可达人口、岗位和目的地形成的需求指标，与实际乘坐量分列 |
| 典型日估算 | 现有模型代表日分配结果，明确标记为估算，与仿真累计值分列 |

单个车站的综合需求可以呈现上车与下车活动总量，但不能把全线各站上下车之和标为全线乘坐人数。换乘站组需要区分外部进出、内部换乘和各线登乘，按指标口径汇总。

小时图来自真实事件时刻或明确标记的典型日预计时刻，历史图保留实际采集日期，不能填造未采样日期。典型日结果同一天重算时替换当天观测，实际累计人次则按事件累积，二者分别存储。每日 0 点归档时处理跨午夜行程，避免重复结算和重复计数。

## 14 城市发展与财政反馈

铁路接入现有公共交通出行选择，支持步行、公交接驳、铁路换乘及直通旅程。完整旅程考虑步行、候车、运行、换乘、票价、拥挤和可用运力，不能只比较列车运行速度。

直通保留同列车旅程；换乘包含下车、通道步行及再次候车；快车跳站限制上下客；容量不足产生等待、改乘或失败。共线、换乘和多入口不能重复创造人口、乘客、收入或岗位。

交通改善通过岗位可达性、就业匹配、居住便利和商业活动影响住宅端与就业端发展。增长仍取决于住房、岗位、真实需求、用地、资金和公共服务，不能因建站就固定涨价或自动出现高楼。

建设费、维护费、车辆成本、运营费及票务收入使用统一账户和每日结算机制。预览展示建设总费用及运营成本估计，共享设施按实际设施归集成本，不能按线路重复收费。

## 15 状态恢复与性能边界

保存车站层级、建筑关联、所有出入口和通道、轨道拓扑、折返与越行设施、共享区间、线路配置、换乘站组、列车及乘客状态、历史数据和随机状态。重新加载后应继续一致运行。

兼容旧存档；缺失的新指标显示尚未采集或按明确规则迁移，不能凭空生成历史。编辑按项目现有撤销和重做规则执行，并恢复对象身份、连接、资金与受影响服务。

删除轨道、车站、建筑或通道后，只更新真实受影响对象，重新检查路径、直通、换乘和折返条件。失败状态必须可定位、可解释和可恢复。

大网络需采用可控的局部更新与缓存失效机制。高速时间推进或画面抽样不能改变权威运力、客流守恒和经济结算结果。交付时说明采用的运行简化与规模边界。

## 16 行为验收

完成代码与界面自查后，先运行集中且与范围相称的自动测试，再以真实界面完成以下流程并保留截图、场景条件及结果。表中的内容是预期行为，不是已经通过的测试记录。

| 场景 | 操作与通过条件 |
| --- | --- |
| 菜单与公交回归 | 三类菜单、缩略图和窄屏操作正常；公交总站前置、道路任意合法路侧选站、双侧吸附、两站 Enter 建线及既有管理能力均可用 |
| 线路地图显示 | 观察菜单开关在地图和精细视图、桌面和窄屏有效，开关不改变运营；共线不同色可辨，站点与实际停靠一致，采用苹果地图公共交通视觉样式 |
| 三层车站 | 分别建设高架、地下、地面地铁站，轨道接口与预览一致，未接轨时正确显示待连接 |
| 站台数量与选点 | 建站时选择不同站台数量，占地、费用和接口随之变化；接轨吸附和线路选点明确对应具体站台；建后增减站台重新校验，保留身份，冲突不部分提交 |
| 已有建筑下建站 | 高架和地面选项禁用；地下站保留原建筑、住户和岗位，建立建筑内部通道及附近室外入口 |
| 入口选址失败 | 无合法地面入口位置时保留草稿，不扣款、不拆楼、不遗留半座车站 |
| 建筑直接进站 | 建筑内人员直接进入地下站，外部乘客可通过合法建筑入口或独立室外入口到站，路径与时间可核查 |
| 入口编辑及拆楼 | 修改、关闭、移动入口后路径和需求更新；拆除关联建筑使内部入口失效，室外入口有效时服务继续 |
| 跨层与道岔 | 合法坡道和道岔可通行，不同高度投影交叉及无道岔转向不能形成假连接 |
| 建线键盘操作 | 两站和多站线路可沿轨道创建，撤回、取消和无效连接提示正确，失败不部分提交 |
| 多线路共线 | 两条以上线路共享区间和站台，调度使用共同容量，排队、延误及班次限制可复现 |
| 火车地铁直通 | 同一列车连续停靠两类车站，乘客不下车继续旅行，换乘次数和收费不重复增加 |
| 车辆兼容 | 不满足站台长度或区间限制的列车配置被明确拒绝，兼容配置可开通 |
| 自动换乘 | 邻近且合法可达的各类铁路站自动组成站组，显示实际通道和时间；障碍隔离时标记未连通 |
| 多层与站组链路 | 垂直连接耗时计入；A 到 B 到 C 仍经过真实通道，没有站组内零时间跳转 |
| 折返与环线 | 开放式线路两端可实际折返，缺设施时不能投入往返运营；环线真正闭合，单向线路有合法循环或回送 |
| 短线和通过列车 | 同站终到与通过列车遵守共同占用规则，折返不会穿越其他列车 |
| 快线与越行 | 无越行设施时快车跟车，有合法设施时安全超过慢车；跳站不能上下客，普通车不会被无限延后 |
| 运营管理 | 修改车型、编组、配车、名称、颜色和运行时间后，列表、列车、运力、费用及乘客选择同步更新 |
| 跨午夜 | 23:30 至次日 01:30 的线路在 00:00 结算后继续发车，01:30 才停止新发车；全天服务、在途行程及每日归档互相一致 |
| 需求与计数 | 车站、线路、方向和小时数据可以按统一事件口径核对，进出站、换乘、直通及多入口均不重复计数 |
| 统计缺失 | 旧存档和未采样日期显示正确缺失状态，代表日估算不伪装成实时人数 |
| 破坏与恢复 | 删除轨道或关闭通道只影响相关服务；恢复连接、撤销、重做和重载后状态与资金一致 |
| 容量与拥堵 | 拥挤、共享轨道瓶颈及低频服务产生合理等待或未满足需求，不穿车、不永久死锁 |
| 规模与交互 | 多线路、多站、多入口及快速时间推进下，状态可解释、操作可用，图表与存档保持一致 |

城市发展验收另设严格对照场景：从同一存档分出两份，保留相同建筑、居民、岗位、道路、轨道、车站、初始资金、政策和随机状态，仅改变目标线路是否运营。公交基线与铁路重构分别验证，避免把其他交通改动混入对照。

在相同模拟日期比较住宅端和就业端的通勤时间、就业匹配、人口入住、住宅开发、商业与办公发展、地价及财政；记录初态、逐日变化、期末差异和机制解释。另设低需求、接驳不良、班次不足、共线拥堵及高运营成本情形，验证交通设施不会无条件促进发展。建设投资回报可用另一个“建设与不建设”的场景单独评估，不能混用两种对照结论。
