# 项目目标与功能规则

本文定义项目要实现的行为和必须保持的约束，是产品规则，不代表所有条目都已完整实现。当前覆盖范围、简化方式与未完成能力见 [实现状态与边界](implementation-status.md)；系统如何执行这些规则见 [系统架构与状态流](city-implementation.md)。

用户在地图上绘制道路、铁路、地铁、有轨电车和巴士服务，城市根据交通条件、人口与就业需求、地价和环境逐步发展。建筑沿可通达的路网生成，住宅区、商业区、工业区、CBD 和副中心由持续的发展过程形成。系统通过可解释的地图、统计和历史记录，让用户理解自己的建设如何改变城市。

产品的核心反馈为：交通建设改变人员与货物流动条件，流动条件改变地块吸引力和土地价值，居民、企业及开发项目重新选址，进而产生新的交通需求。建筑外观、人口、岗位、交通、地价和统计必须共享一致的模拟状态。

本文中的“必须”表示对应功能的验收要求；“应”表示默认实现方向；“可”表示后续扩展。文中给出的初始规模、阈值范围和算法形式属于设计起点，不是已实现能力或经过校准的现实预测。

## 1 产品目标与范围

### 1.1 产品目标

1. 用户通过建设交通网络塑造城市，得到及时、连续且能够理解的反馈。
2. 建筑依据地块条件、需求、收益和建设时间生长，不使用与人口和经济无关的随机摆放作为主体模拟。
3. 人员能够从住宅前往工作、消费和服务设施，并通过道路和公共交通完成组合出行。
4. 地价、房产价格和租金分别建模，影响居民、企业和开发商的选择。
5. 自动形成有空间连续性、功能差异和历史惯性的城区，包括 CBD、居住区、工业区、商业区和副中心。
6. 提供详尽且口径一致的统计，能定位具体对象、追踪历史并比较建设方案。
7. 保留现有地形生成能力，支持本地运行、城市保存和可重复模拟。

### 1.2 用户主要活动

| 活动 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 创建世界 | 选择种子、地貌、范围及地形参数 | 生成地形并展示建设条件 |
| 建设道路 | 绘制、连接、升级、删除道路 | 显示路口、建设成本、受影响地块和连接情况 |
| 建设轨道 | 绘制轨道，设置站点及出入口 | 显示基础设施与可服务区域 |
| 运营公交 | 设置线路、停站顺序、班次和车辆容量 | 显示运行状态、客流、拥挤和成本 |
| 观察生长 | 推进模拟时间 | 展示施工、入住、扩建、空置及城区演化 |
| 诊断城市 | 查看建筑、道路、站点、城区 | 解释发展、衰退、拥堵或无人使用的原因 |
| 比较方案 | 从同一存档创建不同建设方案 | 比较人口、交通、土地市场和财政变化 |

### 1.3 范围边界

完整目标包含道路、步行、巴士、有轨电车、地铁、火车、人员迁移、土地市场、建筑开发和城区识别。数据模型需容纳这些方式及其明确的接入和服务规则。

基础闭环采用地图交互、简化人群与企业模型、代表性时段交通和按月城市发展。以下内容属于可选深化方向，已有部分表达也不代表实现了完整业务：

- 全量居民逐秒活动、逐车道微观交通、精细信号配时。
- 完整房地产金融、抵押贷款、土地竞拍和宏观经济系统。
- 电力、供水、污水等逐段基础设施网络。
- 精细洪水、污染扩散和流体动力学模拟。
- 真实城市数据导入、在线多人协作和完整三维城市。

服务、环境和货运可以先采用明确的简化参数；未建模的因素不得被描述为已经精确计算。

## 2 产品组成与边界

项目由世界生成、交通建设、城市演化、观察分析和本地保存组成。世界生成提供固定的自然条件；建设改变交通与用地；城市演化计算人口、企业、供需与市场；观察分析解释这些变化；存档和方案分支用于持续游玩与比较。

### 2.1 世界与城市分离

生成地形与运行城市是两个阶段。开始建设后，城市使用实际保存的地形，修改显示样式不能重生成地形或重置城市。重新生成世界应作为独立操作处理。

地形栅格提供地表高程和水体信息；道路与地块使用米制矢量几何。地形像素不能作为建筑地块，也不能用放大和插值宣称更高的地基精度。例如 80 km 宽、4096 像素的地形，其横向采样间距约 19.53 m。

### 2.2 规则层与表达层分离

人口、岗位、土地、道路、运营服务及财政由同一城市状态决定。画面可采用不同细节级别和交通抽样，但不能随显示品质改变人口、运力、地价或财政。建筑设施必须说明哪些属性参与模拟、哪些只用于表达。

### 2.3 需求与实现分离

本文中的编号用于定位规则，专题文档说明具体算法和默认参数，实现状态文档说明当前是否满足以及仍有哪些限制。测试日志、版本修订记录、截图及单次实验结果不构成产品规则，也不能替代当前实现说明。

## 3 共用概念与模拟规则

### 3.1 核心对象

| 对象 | 定义 |
| --- | --- |
| 世界 | 固定范围的地形、坐标定义和区域情景 |
| 节点与路段 | 交通网络连接点及连接边，包含通行方向、方式和层级 |
| 街区 | 由地面道路等边界围成的空间单元 |
| 地块 | 可拥有独立用途、开发条件和地价的土地单元 |
| 建筑 | 地块上的实体，包含用途、面积、容量、状态和出入口 |
| 家庭 | 居住与搬迁的基本决策单位，包含人口和收入等属性 |
| 人群 | 具有相近出行及经济特征的人员集合，可以带代表人数权重 |
| 企业 | 岗位与经营空间需求的来源，具有行业和经营状态 |
| 岗位 | 有工作地点及属性的就业机会，可能空缺或已被占用 |
| 站点 | 乘客可以上下车的设施；站台、出入口、换乘连接可分开记录 |
| 线路 | 具有停站顺序和运行路径的服务 |
| 班次 | 某线路的一次运行或规则化发车服务 |
| 出行 | 从一个活动地点前往另一个活动地点的完整旅程 |
| 行程段 | 出行中的步行、乘车或换乘部分 |
| 城区 | 根据实际用途、密度、活动和历史识别出的功能区域 |

### 3.2 时间与计算顺序

**SIM-001 模拟时钟与运行控制**

必须支持暂停、继续、单步推进和加速。界面明确显示模拟日期及速度。城市状态推进独立于屏幕帧率；窗口失焦或渲染速度变化不得改变同样命令序列的模拟结果。

**SIM-002 多时间尺度**

- 地形在建设期间保持静态；建设命令在明确的模拟边界生效。
- 交通先计算典型工作日的早高峰、平峰、晚高峰；休闲出行阶段增加周末或晚间时段。
- 人口、就业、租金、地价和开发按月更新；年度汇总形成城市年鉴。
- 画面中的车辆和行人可以插值动画，但动画数量不直接充当统计真值。

**SIM-003 更新依赖**

每轮更新应按下列依赖处理：建设命令与设施状态 → 需求和出行分配 → 交通成本与可达性 → 居民企业选择与市场更新 → 开发和施工 → 新状态汇总。

新入住或新岗位产生的需求进入下一轮交通更新，或进入有迭代上限的当轮求解。必须固定该规则，避免同一人口在一轮中被重复计算，或用未完成的开发反向决定自身收益。

**SIM-004 随机性与稳定性**

随机种子、随机状态、稳定对象 ID、模型版本和命令顺序必须可保存。同一模型版本、相同初态和相同输入应在约定数值容差内得到相同结果。迁移、价格和用途变化应有调整速度、阈值和惯性，不能因微小扰动在相邻月份持续翻转。

**SIM-005 空城启动与区域情景**

必须提供明确的初始人口或外部迁入需求、初始岗位或对外经济需求、区域增长情景和外部交通连接规则。外部需求有上限并记录来源，不得通过无约束的人口与岗位自动增长维持繁荣。岛屿等场景可以设置抽象区域门户，后续再扩展真实港口或机场。

## 4 世界与建设条件

**WORLD-001 世界创建与建设阶段**

保留现有种子、地貌、范围、起伏、平整度、水位和水系控制。开始城市建设时固定实际地形数据及其版本。重新生成世界属于新建或替换世界操作，必须提示现有城市影响，并提供保留原存档的路径。

**WORLD-002 坐标与单位**

道路、轨道、地块、建筑和站点统一存储为米制世界坐标。显示像素、缩放、设备像素比和导出分辨率不得参与经济或交通计算。与现有左上原点、向东与向南坐标约定衔接时，应集中处理转换。

**WORLD-003 建设适宜性**

应生成陆地、水体、坡度和基本建设难度信息，支持查询某位置为何可建或不可建。开发判断需考虑整个地块的水体相交和地形条件，不能仅检查中心点。

**WORLD-004 水体与地形精度**

海洋、湖泊与连续河道几何共同用于避让；显示上的最小河宽不能自动等同于实际占地宽度。地形采样不足时采用保守建设限制，并保留以后局部细化的接口。插值和放大不得被当作新增真实精度。

**WORLD-005 地形后续修改**

后续地形编辑需单独处理道路、建筑和水体冲突，预览受影响对象并作为可保存的建设事件记录。首版可以锁定建设中的地形，不强制实现局部整地工具。

验收要求：改变视图和缩放后，道路长度与地块面积保持不变；水面地块不能被误判为普通可建设土地；已有城市不会因普通显示设置变化而重建。

## 5 道路与步行网络

### 5.1 道路编辑

**ROAD-001 绘制与编辑**

必须支持连续绘制、端点吸附、路段吸附、取消当前绘制、选择、删除、属性修改和撤销重做。直线、折线和平滑曲线均为当前必需项；曲线以控制点编辑，渲染、交点拆分、地形采样、长度、费用和寻路使用同一条真实几何。选中道路后可拖动控制点修改，并保留稳定道路 ID。操作预览显示长度、类型、连接关系、冲突及成本；错误须指向具体位置。

**ROAD-002 道路属性**

至少包含道路类别、宽度、方向、允许通行方式、自由流速度、容量、层级、建设及维护成本、临街出入口许可。道路类别至少能够表达地方街道、主干道和限制出入口道路。

车道数可用于推导简化容量，但首版不要求逐车道车辆模拟。容量参数必须记录单位和适用时段。

**ROAD-003 路口与拓扑**

同层且允许连接的道路交叉时建立节点并拆分路段；端点落到路段时形成连接；接近但未吸附的道路不得隐式连通。拆分后保留原路段的属性、引用映射和线路关联。

必须处理重复线、零长度段、自交、极短路段和方向冲突。高架或地下交叉只有存在明确连接设施时才可通行。

**ROAD-004 跨河与坡度**

跨水路段需显式采用桥梁或其他允许的结构；坡度过大时禁止普通道路或要求工程处理。地面、高架、地下及其连接段分别计算条件与成本。复杂工程可在明确范围内拒绝，但必须给出原因，基础桥隧能力应保留。

### 5.2 步行和建筑接入

**ROAD-005 步行网络**

普通街道可按规则生成步行连接，限制出入口道路不得默认允许步行。路口过街、独立步道和车站出入口通过明确的边接入网络。河流、围挡和未连接层级不能仅凭距离跨越。

**ROAD-006 出入口**

建筑出入口连接到允许服务其地块的道路或步道。与道路几何接近不等于获得服务；高速公路旁地块须通过地方道路接入。工业和仓储需要满足货运接入条件。

**ROAD-007 升级与拆除影响**

道路升级、改向和拆除需更新地块接入、线路路径、交通分配及可达性。受影响的建筑标记失去连接，受影响线路标记中断或重新求路；不能让车辆继续沿已删除路段运行。局部编辑不得随意重建远处地块或改变其 ID。

**ROAD-008 撤销语义**

同一暂停编辑批次内支持撤销重做。模拟已经推进后，历史建设的撤销应通过恢复检查点或新的反向建设命令处理，并明确说明是否恢复居民、价格和历史；不能只恢复道路图形而保留不一致的模拟状态。

验收要求：十字交叉、丁字连接、断头路和单向道路具有正确连通性；高架跨越不自动产生路口；删除唯一接入道路后，出行和开发判断同步变化。

## 6 街区与地块

**PARCEL-001 开放道路旁的开发**

单条道路、支路和尽头路两侧均可生成临街地块，不要求先形成闭合街区。地块应有可调的临街宽度、进深、最小面积和形状约束，并留出道路空间。

**PARCEL-002 闭合街区与细分**

地面道路形成闭合空间时识别街区，扣除道路占地后细分地块。细分需保证可开发地块具有可行接入，合理处理街角、狭长和不规则形状。地下轨道或无地面占地的跨越结构不得仅因投影闭合而生成街区。

**PARCEL-003 大街区内部**

用户只需绘制主要道路。默认自动补充社区支路、建筑入口小径及邻近建筑之间的步行连接；提供关闭自动配套选项。自动道路也必须进入真实网络，受地形、预算、合法连接和既有建筑约束。没有实际接入的内部土地保持未开发；不得为了填满街区而先生成无路建筑。

**PARCEL-004 几何合法性**

地块不得与道路、水体、其他地块发生非法重叠。裁剪后的碎片按照最小面积和接入规则合并、保留或标记不可建。面积、边界和可开发面积分别保存。

**PARCEL-005 地块属性与稳定身份**

至少保存边界、临街边、出入口候选、面积、坡度摘要、可建面积、用途约束、开发强度限制、地价、建筑关联和生成来源。道路编辑时，只重算受影响范围，并明确地块分割、合并及其建筑的处理方式。

**PARCEL-006 用途控制**

默认由模拟选择用途。后续可提供用途偏好、保护区和高度或容积率限制，作为用户引导发展的方法；形成住宅或 CBD 不应依赖用户手工涂满分区。

验收要求：一条道路即可产生合法临街地块；闭合街区能细分；大街区腹地不会无接入开发；建筑位置不因全局重新细分而随机漂移。

## 7 建筑与开发

### 7.1 建筑数据与形态

**BUILD-001 建筑用途**

首个城市生长版本包含住宅、零售商业、办公、工业与仓储，工业和仓储可先共享部分规则但保留用途区分。支持混合用途数据，后续显示底层商业与上层住宅等组合。

**BUILD-002 形态与容量**

建筑包含轮廓、朝向、占地面积、楼层、总建筑面积、可使用面积、各用途面积、住宅单元数、岗位空间和出入口。形态须服从地块边界、退界和强度限制。

建筑面积不能完全一致。不同用途应采用不同占地与长宽比例分布，同类建筑也须有稳定、可复现的尺寸差异，并随地块面积和开发强度变化。住宅、商铺、办公楼、厂房及仓库应在实际轮廓上呈现区别；人口与岗位容量、租金和建设成本须跟随真实面积计算，不能只缩放外观。界面应分别展示建筑占地面积与总建筑面积。

住宅容量由住宅单元及面积规则推导；岗位容量由实际经营用途和面积参数推导。模型需区分容量、已占用空间、实际人口和已就业人数。

**BUILD-003 视觉表达**

不同用途、规模和年代具有可识别形态；高层、低层、厂房和仓库不能只以颜色区分。首版可采用简化轮廓、屋顶及阴影。远景汇总城区，近景展示建筑，选择对象时显示详细属性。

### 7.2 开发决策与生命周期

**BUILD-004 开发候选**

系统按地块分别评价住宅、商业、办公和工业仓储用途，并同时满足：可建且有接入、存在有效空间需求、允许该用途与强度、预期收益能够覆盖成本。

**BUILD-005 开发收益**

预期收益考虑可出租面积、用途租金、预期入住率和收益周期；成本包括土地取得、建设、地形处理、拆迁及必要接入。开发能力和资金使用简化预算上限表达，避免一个月份启动无限项目。

在建项目须计入未来供应；同一需求不得被多个项目重复满足后仍继续无限开工。

**BUILD-006 生命周期**

至少支持计划、施工、可使用、部分空置、完全空置、更新或拆除状态。施工消耗模拟时间，完成后才增加可用容量。扩建、用途转换和重建具有相应成本、时间和几何约束。

**BUILD-007 入住与迁入**

竣工不自动创造人口或就业。家庭及企业通过选址匹配占用空间；岗位产生、招聘和人口迁移分别记录。改建占用中的建筑时，原住户和企业必须迁移、安置或离开，并写入统计。

**BUILD-008 空置与衰退**

需求不足、接入中断、租金过高或环境恶化可能导致空置。持续空置才触发进一步衰退、改用途或拆除，不允许单个时段交通波动立即摧毁建筑。

**BUILD-009 原因解释**

选中地块或建筑，展示当前状态、容量、占用、租金、主要开发因素和主要阻碍。解释必须来自模型中的约束与贡献项，例如“道路未连通”“办公需求不足”“预计收益不足”。

验收要求：未竣工建筑不贡献可用容量；有建筑而无入住时人口不增加；需求低时仍可能有空地；土地变贵不会绕过成本和需求判断直接生成高层。

## 8 人口家庭与迁移

**PEOPLE-001 人群与家庭属性**

至少记录居住位置、家庭人数、收入组、劳动人口、就业情况、汽车可用性及住房占用。首版可以使用带人数权重的家庭群组；权重必须用于所有人口和出行统计，并能正确分拆与合并。

**PEOPLE-002 城市迁入迁出**

外部迁入由区域情景、可用住房、工作机会、可负担性和城市吸引力共同约束。迁出由失业、住房负担、可达性和外部吸引力等因素产生，需记录主要原因。无房可住或无路可达不能通过强制塞入建筑解决。

**PEOPLE-003 城内搬迁**

家庭比较当前与候选住房的租金、面积、通勤、生活服务、环境和搬迁成本。存在可行收益且超过迁移阈值后才搬迁，防止每月无成本重新选址。

**PEOPLE-004 不同人群偏好**

收入、汽车可用性、家庭规模等属性影响住房预算、费用敏感性和出行选择。首版通过明确参数表达差异；不能让所有人无条件选择同一条最快路线或同一个最高评分住所。

**PEOPLE-005 未满足需求**

记录未获得住房、未匹配工作、无法通勤和被迫搬迁的人口。首版可采用“未安置需求池”而不绘制无住所个体，但需与已入住常住人口区分，且不能重复统计。

**PEOPLE-006 人口收支**

每期人口变化满足：期末人口 = 期初人口 + 迁入 − 迁出 + 出生 − 死亡。首版如不实现出生死亡，两项明确为不启用，不能由不明增长系数替代。城内搬迁只改变空间分布，不改变全市人口。

验收要求：全市人口能够由建筑入住和相关人口状态汇总复核；群组分拆不改变人数；住房不足会影响迁入；城内搬迁不会产生额外人口。

## 9 企业岗位与外部经济

**ECON-001 企业与行业**

企业至少区分零售、办公服务、工业和仓储等类别，记录经营位置、所需空间、岗位、已招聘人数、经营状态和运输需求。首版可以按行业群组建模。

**ECON-002 岗位与就业匹配**

区分岗位容量、实际设立岗位、已就业人数和空缺岗位。匹配考虑可达性与基本人群条件；每名劳动者或其权重份额不能同时占用多个全职岗位。

**ECON-003 企业选址**

零售主要受消费人口和活动流量影响；办公受劳动力可达性、商务集聚和租金影响；工业与仓储受货运成本、地块规模和地价影响。企业只有在合适空间存在时才能入驻。

**ECON-004 外部经济与需求**

允许对外服务、贸易和区域需求支持初始经济。外部输入与本地消费分开记录，避免企业收入全部依赖尚未存在的本地人口。外部增长参数可调但有明确边界。

**ECON-005 经营变化**

企业可扩张、收缩、迁址和关闭。首版采用收入与成本近似值及持续状态阈值；企业关闭释放空间和岗位，受影响劳动人口进入重新匹配。

**ECON-006 货运**

工业和仓储应具备货运接入及到区域门户的运输成本。首版可以使用汇总货运需求和道路货运时间；后续加入货运车流、铁路货场和客货服务区分。未建设铁路货运设施时，不得把客运站视为货运入口。

验收要求：新增岗位不直接等于新增就业人口；关闭企业后岗位和空间状态正确释放；地价或运输成本变化能够影响不同企业的选址评价。

## 10 人员出行与交通分配

### 10.1 需求产生

**FLOW-001 出行目的**

完整版本包含工作、上学、购物、休闲及返程。首版必须实现住宅到工作地点的通勤及基本消费出行；学校和公共服务设施可在后续加入。每类需求定义出行频率、时段和目的地选择规则。

**FLOW-002 出行对象与时段**

每次出行或汇总出行组包含起点、目的地、人数权重、目的、出发时段、可用交通方式和完成状态。保留早晚方向差异，返程不能被错误归入单向出行或重复生成。

**FLOW-003 目的地选择**

工作地点来自岗位匹配；购物及休闲目的地根据服务容量、吸引力和出行成本选择。人口增多可以增加需求，但必须有对应的家庭或活动依据。

### 10.2 路径与方式选择

**FLOW-004 完整旅程**

允许步行、汽车、步行接驳公交及多线路换乘组合。路径从建筑出入口出发，到目的建筑出入口结束。不得仅计算站到站时间而遗漏首末段步行。

**FLOW-005 广义出行成本**

至少包含行驶或步行时间、候车、换乘、费用、拥挤，以及相应人群的偏好权重。费用通过时间价值等规则换算后才能与时间组合；界面仍分别展示分钟与货币成本。

**FLOW-006 不可达处理**

无合法路径、停止运营、车辆不可用或超出可接受条件时，记录原因并尝试其他方式、时段或目的地；无法解决的需求记为未完成。不可达不得编码为零分钟，也不得从统计分母中默默删除。

**FLOW-007 交通拥堵**

道路出行时间随流量、容量和路口等条件变化。首版使用经过校准的汇总延误关系及有上限的迭代分配；不要求逐车模拟，但不能无视容量或把所有出行永久压在同一条初始最短路上。

**FLOW-008 有限容量与选择反馈**

公共交通超载导致等待、滞留、改道或未完成出行；道路拥堵改变后续分配和可达性。迭代设定收敛条件、最大轮次和异常回退，保证计算可结束。

**FLOW-009 展示与统计一致**

动画可展示抽样车辆和行人，并明确属于抽样。客流、车流和人口统计来自实际分配结果，不能通过数屏幕图标得出。汽车出行的人数和车辆数通过乘员系数转换，单位必须明确。

验收要求：同一人次在完整出行和行程段中可追踪；换乘不增加完整出行次数；巴士可因拥堵变慢；无桥的河流不能被步行直接穿过。

## 11 公共交通基础设施与运营

### 11.1 共用模型

**TRANSIT-001 三层对象**

基础设施、站点设施和运营服务必须分开。铺设轨道不等于已有客运；建设站台不等于列车停靠；线路服务必须引用实际可运行路径、停站顺序和运营参数。

**TRANSIT-002 站点与接入**

站点包含位置、所属方式、服务方向、站台容量或简化约束、出入口和步行连接。站点覆盖范围按网络步行成本计算；圆形半径仅可作为辅助示意。

**TRANSIT-003 换乘**

不同线路通过可行步行连接换乘。相交轨道、上下叠置站台或空间邻近站点不能自动视为零成本换乘。换乘连接需包含时间及方向限制。

**TRANSIT-004 线路编辑**

支持创建、命名、颜色、方向、停站顺序、运行路径、停用和删除。校验站点顺序与路径、道路方向、轨道连通性和交通方式兼容性；显示失效原因。

**TRANSIT-005 运营参数**

至少提供运营时段、发车间隔、车辆或编组容量、停站时间、车辆速度约束和运营成本。服务速度由车辆、线路、停站及拥堵共同决定。

**TRANSIT-006 运力与车队**

根据往返时间、折返停留、发车间隔计算所需车队或等价运营资源，并计入成本。用户不能在不增加资源和成本的情况下无限缩短班次。

**TRANSIT-007 候车计算**

高频、均匀发车且随机到站的服务可用发车间隔一半近似初始候车时间。低频或按时刻表服务应逐步采用下一班可用班次寻路；满载后的额外候车独立处理，不能继续使用固定半间隔掩盖容量不足。

### 11.2 方式差异

| 方式 | 基础设施 | 首要运行规则 | 主要统计 |
| --- | --- | --- | --- |
| 巴士 | 可通行道路及站点 | 受单向、拥堵和停站影响；后续支持专用道 | 行程时间、客流、满载、运营成本 |
| 有轨电车 | 轨道、道路共享区或专用走廊 | 区分混行与专用路权，保留站点及换乘 | 走廊客流、延误、运力利用 |
| 地铁 | 地下、地面或高架轨道与出入口 | 通过实际出入口接入步行网络，容量约束 | 断面客流、拥挤、换乘压力 |
| 火车 | 区域轨道、车站及外部联系 | 较低频服务支持时刻表；客货分别建模 | 区域通勤、站点客流、运输量 |

**TRANSIT-008 巴士**

巴士路径必须沿允许的道路运行。道路改向或拆除后重新校验线路。即使车站仍在原位置，线路中断也不能继续为地块提供原有可达性。

**TRANSIT-009 有轨电车**

轨道和路权类型分别存储。混行区受道路拥堵影响，专用区按自身运行约束计算；不能仅通过更换巴士图标实现。

**TRANSIT-010 地铁**

区分轨道几何、站台和出入口。不同高程或深度的连接通过明确换乘边表达；地铁经过地块下方但无可达车站时，不给予站点接入收益。

**TRANSIT-011 火车**

支持城市内部与区域外部联系。客运和货运设施、线路及需求分开。首期城市铁路可以采用简化班次，低频长距离服务阶段加入时刻表约束。

**TRANSIT-012 网络变更**

修改班次、关闭站点或删除轨道后，重算相关服务及全局必要的出行分配。客流、土地吸引力与价格按各自时间尺度响应，不在编辑完成瞬间直接重建整片城区。

验收要求：只有轨道没有服务时无客流；增加班次需要相应资源；两条线路相交但无换乘连接时不可换乘；满载线路出现受限需求。

## 12 可达性与交通服务水平

**ACCESS-001 可达性类型**

至少计算居民到岗位、人口到商业服务、企业到劳动力、工业仓储到货运门户的可达性。按交通方式、时段和人群分别计算，不使用单一“附近有站”布尔值代替。

**ACCESS-002 时间预算**

提供 30、45、60 分钟等可配置时间预算下的可达机会数量。第一版可先提供 30 分钟岗位可达性。必须包含接驳、候车和换乘时间，并显示计算时段。

**ACCESS-003 机会与容量**

“可达岗位总量”和“可达空缺岗位”分别统计。前者表示机会空间，后者用于求职匹配。商业设施的存在与实际服务容量也应区分。

**ACCESS-004 缓存与失效**

网络、运营、拥堵或机会分布变化时，相关可达性缓存失效。局部几何编辑可以局部更新，但可能改变全城路径的连接变化必须触发必要的全局更新。

**ACCESS-005 地图与解释**

选中住宅或站点可展示网络等时圈、可达岗位和主要障碍。隔河无桥、无步道、无服务或严重拥挤时应体现损失，并允许查看具体旅程。

验收要求：没有过河通道时，对岸岗位不因直线距离近而计入；关闭运营线路会改变公交可达性；新增无实际用途的线路不保证提升全城指标。

## 13 地价房产价格与租金

### 13.1 指标定义

| 指标 | 口径 | 用途 |
| --- | --- | --- |
| 土地单价 | 每平方米土地的模型估值 | 地块比较与土地取得成本 |
| 地块总价 | 土地单价乘土地面积，并按约定规则处理特殊约束 | 开发成本与资产统计 |
| 房产总价 | 含土地权益与建筑的物业模型估值 | 物业价值统计，不能再次叠加土地价值 |
| 单位租金 | 每平方米可出租面积每月的租金 | 企业和家庭空间成本 |
| 住宅单元租金 | 某住宅单元每月总租金 | 家庭住房负担 |

首版使用统一的模拟货币单位，并明确时间和面积单位。若没有成交模拟，界面使用“模型估值”，不得将其标记为真实成交价。

### 13.2 价格形成

**LAND-001 地块价格状态**

每个地块保存土地单价、估值时间、变化量和主要驱动因素。建筑按用途分别保存租金；混合建筑的不同用途空间不能共用一个未经区分的租金。

**LAND-002 地价驱动**

至少考虑就业与消费可达性、步行和公共交通服务、环境与生活服务、允许开发强度、土地稀缺、用途需求、集聚，以及噪声、污染和建设成本。

交通改善可以提高某些用途的支付能力，但效果受需求、供给、容量和负面影响制约，不能设置“新站周围固定涨价百分比”作为唯一逻辑。

**LAND-003 用途竞争**

不同用途根据经营或居住支付能力形成土地需求。办公中心可能在高可达区域竞争土地，住宅偏好同时受环境和住房负担影响，工业仓储重视运输与低成本大地块。

地价应依据受约束的支付能力或预期土地剩余收益形成；开发判断使用一致的价格快照或有界迭代，避免“预期涨价 → 无限开发 → 再次涨价”的无需求自激循环。

**LAND-004 租金与空置**

各用途租金随有效需求、可用供应、空置率和区位品质调整。在建供应影响预期，但竣工前不计入现有可出租面积。高空置率可以压低租金或抑制新项目。

**LAND-005 调整速度与惯性**

价格按月或明确周期更新，设定调整幅度、上下界与平滑规则。短期交通扰动不能在一个动画帧内导致全市价格突变。无需求地块可以低价或长期未开发，不强制保持上涨。

**LAND-006 房产估值**

物业估值方法须固定并可解释，可以采用受限的租金收益资本化或成本法。若租金资本化已体现土地价值，汇总时不得再加一次土地价格。

### 13.3 社会与空间影响

**LAND-007 可负担性**

家庭在住房与交通支出之间权衡。至少展示住房支出占收入比例和住房加交通支出占收入比例；收入为零或无有效分母时显示特殊状态，不产生无穷大或虚假零值。

**LAND-008 迁移与替代**

租金持续超过可负担水平可引发搬迁或迁出；工业仓储可以因地价上涨迁往外围。移动仍受空置空间、交通和搬迁成本约束，不能瞬间找到无限替代位置。

**LAND-009 供给反馈**

新增住房或经营空间可以缓解短缺，减弱价格压力。道路与公交改善后，需求增加与供给增加的相对速度共同决定价格变化，不要求所有改善都导致涨价。

**LAND-010 地图和历史**

提供地价、用途租金、空置率和涨跌幅图层；支持查询单地块历史及城区分布。提供中位数、分位数和分布，避免只用全市均价掩盖差异。

验收要求：地价与租金单位明确；低需求站点不会固定涨价；增加住房供应能够进入租金更新；房产与土地总值不重复汇总。

## 14 自动城区与城市演化

**DISTRICT-001 识别依据**

城区由实际建筑用途、建筑面积、人口、岗位密度、活动强度、空间邻接和持续时间识别。交通可达性用于解释区位，并可辅助中心性判断。行政式命名或用户涂色不能替代实际识别。

**DISTRICT-002 城区类型**

至少支持居住区、商业区、工业仓储区、办公集聚区、CBD、混合区和未形成主导用途的区域。CBD 需同时满足较高办公商业集聚、就业或活动强度、中心性及一定规模，不能仅以建筑高度判定。

**DISTRICT-003 自然形成条件**

住宅受工作可达、住房负担和环境影响；商业受消费与活动人流影响；工业仓储受货运和土地条件影响；办公受劳动力可达与集聚影响。地形、水体、交通连接和历史开发共同形成空间差异。

**DISTRICT-004 集聚与副中心**

集聚收益应饱和，并存在租金、拥挤和土地供给约束。城市可以形成主中心和多个副中心，也可以保持小规模、分散或沿走廊发展；不强制每张地图产生同样数量的 CBD。

**DISTRICT-005 历史惯性**

使用进入、退出阈值及持续期稳定标签，避免一个月办公比例变化就频繁改名。城区分裂、合并和中心转移保留历史关联。

**DISTRICT-006 城区查询**

显示主导用途、人口、日间活动人口、岗位、地价租金分布、交通方式占比、发展阶段和主要变化原因。居民区昼夜人数差异应来自人员流动。

验收要求：成熟中心可以在合适条件下出现；小规模城市允许没有 CBD；高层住宅不被自动认定为 CBD；副中心的产生有交通和需求依据。

## 15 环境公共服务与财政

**ENV-001 环境影响**

基础阶段提供道路或工业邻近带来的简化噪声、污染和景观品质因子，并标记为模型指数。后续可增加扩散与排放模型；未建立物理量换算前，不显示具有现实精度含义的浓度。

**ENV-002 公共服务**

学校、医疗、公园和其他服务设施作为后续功能，包含接入、容量、服务吸引力和成本。服务覆盖按网络可达性计算，并能够影响人员出行和住宅吸引力。

**ENV-003 排放与风险**

交通排放估算使用公开或明确配置的排放系数、车辆里程和动力类型，记录版本与单位。洪水等风险在独立模型建立前仅允许使用明确命名的地形代理指标，不能由湿度直接宣称得到洪水概率。

**FIN-001 建设与维护成本**

道路、桥隧、轨道、站点、车辆和设施分别记录建设及周期维护成本。免费建设的沙盒模式仍保留成本账目，便于比较方案。

**FIN-002 运营收支**

公交成本至少随车队、服务里程或运行时间变化；收入依据票价规则和实际付费旅程计算。若按完整旅程收费，换乘不得重复收费；若实施其他票制，必须明确。

**FIN-003 财政模式**

默认可先采用无破产限制的沙盒，后续增加预算约束、税收和补贴。预算约束是否启用必须可见。土地升值不自动成为政府现金收入。

验收要求：增加班次会改变资源需求及运营成本；预算模式与统计账目一致；估算指标具有明确单位或被标为指数。

## 16 统计专题地图与城市年鉴

### 16.1 统计共用规则

**STAT-001 单一数据来源**

统计从建筑、家庭、企业、岗位、交通分配和财政事件中汇总。不得为图表单独生成脱离模拟的随机趋势。每个指标记录单位、空间范围、时间范围、计算版本及有效样本口径。

**STAT-002 多层查询**

支持全市、城区、自选范围、地块、建筑、道路、站点和线路查询。自选范围的跨界对象按明确的归属或分摊规则统计；同一仪表盘内使用一致时间快照。

**STAT-003 时间与分母**

区分时点存量、期间流量和累积值；区分工作日高峰、代表性日、月度和年度。代表性日推算年度时明确放大系数。缺失值和零值分别显示。

### 16.2 指标目录

| 类别 | 必需指标 | 计算口径或补充说明 |
| --- | --- | --- |
| 人口 | 常住人口、家庭数、迁入、迁出、城内搬迁、未安置需求 | 迁移为期间流量；城内搬迁不改变全市人口 |
| 住房 | 住宅单元、可用单元、入住率、空置率、在建供应 | 分母仅含已竣工且可使用单元 |
| 就业 | 劳动力、设立岗位、已就业、失业、空缺岗位 | 失业率分母为劳动力；无劳动力时显示不适用 |
| 企业 | 企业数量或权重、行业构成、新增、关闭、迁址 | 群组不能直接当作单个真实企业数量 |
| 建筑 | 数量、用途面积、楼层分布、建筑年龄、施工与更新量 | 混合用途按面积分配 |
| 土地 | 可建面积、已开发面积、建成区面积、容积率、开发强度 | 容积率分母为约定地块土地面积 |
| 密度 | 全域人口密度、建成区密度、居住用地密度、就业密度 | 分母随指标名称固定，不能混用 |
| 土地市场 | 土地单价分布、用途租金、物业估值、涨跌幅 | 中位数和分位数；说明按地块还是面积加权 |
| 住房负担 | 租金收入比、住房与交通支出收入比、超负担人口 | 明确收入时间单位、特殊收入处理和阈值 |
| 出行 | 需求人次、完成人次、未完成人次、目的、方式占比 | 完整出行计数，独立显示未完成比例 |
| 通勤 | 平均、中位数、P90 时间、距离、候车与换乘时间 | 成功出行的时间分布与失败比例并列展示 |
| 道路 | 分时流量、车辆里程、人员里程、延误、容量利用 | 区分人次、车次及其时段 |
| 公交 | 完整旅程、上车人次、站点上下车、换乘量、断面客流 | 一次换乘旅程可以产生多次上车 |
| 公交服务 | 运行时间、候车、滞留、满载率、服务覆盖人口 | 满载率按车次或区间容量；明确峰值或平均值 |
| 可达性 | 时间预算内岗位、空缺岗位、服务机会 | 按人群、方式、时段分组 |
| 城区 | 用途组成、主副中心、日夜人口、功能转移 | 基于实际活动与城区历史 |
| 财政 | 建设费、维护费、运营费、票款、补贴、净收支 | 区分一次性支出与期间支出 |
| 环境 | 模型噪声与污染暴露、估算排放、景观条件 | 没有物理标定的结果使用指数 |

**STAT-004 方式占比**

方式占比以已完成的完整出行为分母；未完成需求单独展示。完整出行按约定主方式分类，例如含轨道的组合旅程归入对应主方式，多种轨道混用时按固定优先级或最长乘车段归类，详细行程段另行展示。必须公开分类规则；分母大于零时，各方式占比总和为 100%，且不重复计算换乘；没有已完成出行时显示不适用。

**STAT-005 流向图**

提供居住地到工作地的 OD 流向、跨区通勤、迁入迁出和线路客流方向。OD 指起点与终点配对。大规模视图按区域聚合，小规模查询可展开到建筑或代表性人群。

### 16.3 专题地图

**STAT-006 地图图层**

至少支持用途、人口与就业密度、交通流量、拥堵、公交客流、站点网络覆盖、岗位可达性、地价、租金、空置率和开发状态。后续加入噪声、污染、服务和建设成本。

每个图层展示单位、时间、范围和图例；价格与流量等偏态数据可使用分位数或对数图例，并标明方式。颜色之外应有数值、图例或形态辅助。

### 16.4 历史与解释

**STAT-007 历史时间序列**

按月保存核心指标，保留年度汇总和关键对象事件。历史数据的压缩策略必须明确，不能在用户查看旧年份时用当前状态重算并覆盖历史。

**STAT-008 城市年鉴与事件**

记录新增中心、通勤改善、空置增加、产业迁移和线路拥挤等事件。事件具有触发阈值、持续期和冷却时间，避免每轮重复通知。叙述引用实际变化及对象，不虚构原因。

**STAT-009 解释边界**

单次运行中的前后变化可表述为“建设后观察到的变化”，不能自动宣称全部由该建设导致。模型评分贡献可以解释决策依据；严格的方案影响分析使用对照分支。

**STAT-010 导出**

保留地图 PNG 导出，增加统计 CSV 与情景摘要导出。导出包含单位、模拟时间、筛选条件、模型版本和是否为推算值；CSV 在常用表格软件中可正确读取中文。

验收要求：总人口与下钻数据一致；有换乘时上车人次可大于完整公交出行数；P90 不掩盖无法出行人群；相同快照的地图与图表一致。

## 17 用户界面与操作反馈

**UI-001 工作模式**

界面区分世界创建、道路建设、轨道建设、公交运营、城市观察和统计分析。建设阶段以地图为主，工具和属性面板按当前对象出现；地形参数不占据主要建设空间。

**UI-002 工具冲突与键盘**

平移、选择、测距和绘制有明确状态。Esc 取消当前操作或退出工具，撤销重做有快捷键，绘制中不能误触发整个世界重新生成。保留缩放、适应地图等基本操作。

**UI-003 即时预览**

绘制预览、吸附、长度和连接提示即时显示；需要后端确认的操作标记等待状态。命令被拒绝时保留可修正的输入和明确原因，不能留下已显示但未实际存在的道路。

**UI-004 对象详情**

建筑、地块、道路、站点、线路及城区均提供基础属性、当前状态、历史和原因说明。选中失效线路时能够定位中断路段；选中无法开发地块时能够定位约束。

**UI-005 城市反馈**

提供简洁的关键指标与可展开的统计。重要事件可以定位地图和查看历史；普通数值变化不持续弹窗打断建设。

**UI-006 可访问性**

交互工具具有文字标签和键盘操作路径；专题图不只用红绿区分；数值附单位；动画遵循减少动态效果设置。主要界面以中文呈现。

**UI-007 地图层级与缩放**

支持从区域总览缩放到街道和单栋建筑可操作的尺度。缩放上限应按世界范围及建筑操作需要确定，不沿用当前固定倍数作为最终限制。远景聚合道路与城区，近景展示建筑、出入口和站点细节；切换细节等级不改变实际几何和统计。

验收要求：用户能够从地图完成一条道路、一条公交服务和一次对象诊断；切换工具不破坏尚未提交的状态；错误信息能指导修正。

## 18 存档恢复与方案比较

**SAVE-001 完整存档**

必须保存地形实际数据、世界范围与坐标、网络、站点线路、地块建筑、人口企业岗位、市场状态、模拟日期、区域情景、随机状态、模型版本和必要历史。保存种子仅作为来源信息，不能替代实际地形。

**SAVE-002 保存原子性与恢复**

手动保存与自动保存均写入一致时间点快照。写入失败保留上次有效存档；损坏存档应明确报错，并允许恢复最近检查点。读取成功前不得部分替换当前城市。

**SAVE-003 版本兼容**

存档包含格式版本和模型版本。支持的旧版通过明确迁移转换，无法处理时提示原因并保留原文件。模型变化后的结果不可继续宣称与旧版数值完全相同。

**SAVE-004 建设命令与检查点**

为关键建设保存命令记录和阶段检查点，支持复现、问题定位和方案分支。所有被引用对象使用稳定 ID，删除和替换有明确映射。

**COMPARE-001 分支方案**

从同一检查点创建至少两个独立方案，修改道路、线路或班次后分别推进相同时长。方案修改不影响原存档。

**COMPARE-002 比较条件**

比较时展示共同初态、模拟期限、情景参数和模型版本。尽量使用按对象或事件分流的随机序列减少随机干扰；相同种子本身不保证分支后随机事件一一对应。

**COMPARE-003 比较输出**

展示人口、住房、就业、通勤、可达性、客流、地价租金、空置率和成本差异，并支持地图定位受益与受损区域。不得预设新线路一定改善所有指标。

验收要求：保存后继续与重新读取后继续的结果在约定容差内一致；比较分支相互隔离；缺少模型版本或条件不一致时不能无提示混合比较。

## 19 技术与非功能要求

### 19.1 架构约束

**TECH-001 职责分离**

保留 Electron 与 Python 底座。前端负责工具交互、渲染和查询展示；后端负责权威城市状态、几何计算、模拟及存档。前端可以预览，但不能维护与后端互相独立的人口或价格真值。

建议模块边界为世界、网络、地块、建筑、人口、企业、出行、公交、可达性、土地市场、城区、统计和存储。模块间通过明确输入输出连接。

**TECH-002 几何工具**

可评估 Shapely 的缓冲、相交、裁剪、成面和空间索引能力；具体版本在开发时固定。二维几何相交与交通层级连通分开处理，不依赖几何库自动推断桥隧连接。

**TECH-003 API 与增量**

新增建设命令、模拟控制、对象查询、统计、存档接口。返回命令 ID、城市版本及结果；拒绝过期命令或提供明确重试策略。城市运行使用状态增量或分块快照，避免每次操作重新传输全部地形。

当前地形接口的请求体限制和静态资源白名单需要按新功能调整，不能直接把完整城市塞入地形生成参数接口。

**TECH-004 空间与计算分层**

道路和地块使用空间索引；渲染采用可视范围裁剪和多级细节；交通先按区域及人群聚合，再根据需要细化。高成本计算移出界面主线程。

局部开发只需更新相关建筑与邻域，关键桥梁或主干线路变化可能影响全网。性能优化不得牺牲这一依赖。

### 19.2 性能与规模

**NFR-001 首期规模**

首个可玩场景以约 8 × 8 km 建设范围验证闭环，保留现有更大地图的展示能力。地形范围上限不等于同等范围可承载的城市规模，必须分别说明。

**NFR-002 性能验收基准**

进入城市生长阶段前固定基准机器、操作系统、建筑数、网络边数、人口权重、线路数、时段数及计算精度。建议先用 1 万栋建筑、1 万条网络边、10 万模拟人口和 20 条公交线路作为压力场景候选，实测后确定受支持规模。

初始性能目标为：常规地图操作的第 95 百分位输入反馈不超过 100 ms；常规视图维持至少 30 FPS；超过 1 s 的操作展示进度或忙碌状态，且界面仍可响应。模拟月耗时、内存与存档时间需随基准场景实测后设定上限，不能在没有基准的情况下宣称达标。

**NFR-003 一致性与可恢复性**

禁止负人口、负容量、非法几何、重复岗位占用和悬空引用进入已提交状态。出现数值发散或求解未收敛时使用明确的回退结果并标记，不得静默输出看似正常的统计。

**NFR-004 本地与离线**

核心生成、编辑、模拟、保存和查询不依赖云服务。延续现有 Electron 隔离及本地服务访问控制；后续联网导入作为独立可选功能。

**NFR-005 可调参数**

出行偏好、容量、需求、开发周期、价格调整、迁移阈值和城区识别阈值集中配置、带单位和版本。校准配置可以随存档保存，避免隐藏常数散落在界面代码中。

## 20 功能依赖与闭环

| 上游条件 | 下游行为 | 必须保持的约束 |
| --- | --- | --- |
| 固定世界与米制坐标 | 道路、地块、建筑、站点 | 所有计算共用同一空间单位和地形 |
| 可通行交通图 | 地块接入、通勤、服务与货运 | 几何靠近不能代替网络连通 |
| 地块及建设条件 | 用途竞争、施工、公共设施 | 占地真实且互不冲突 |
| 可用住房和岗位 | 迁入、就业及活动 | 施工容量不能直接变成人口或就业 |
| 实际需求和供给 | 地价、租金、经营和开发 | 在建供应预留，不能重复消耗需求 |
| 线路、班次及容量 | 公共交通组合旅程 | 有轨道而无运营服务不能产生客流 |
| 共同统计口径 | 地图、详情、历史与导出 | 同一事实不能随展示位置改变 |
| 完整状态和随机状态 | 恢复、继续与方案比较 | 比较必须显示初态、期限、参数及模型条件 |

地价、租金、人员流动与就业匹配属于城市闭环的组成部分。城市形态来自这些机制共同作用；需求不足或网络条件不合适时，没有形成 CBD、没有新楼开工或存在空置都是允许的结果。

## 21 综合验收场景

| 编号 | 场景与操作 | 预期结果 |
| --- | --- | --- |
| AC-01 | 在平坦陆地绘制一条普通道路 | 两侧形成合法临街地块，无需闭合街区 |
| AC-02 | 绘制十字路口、高架跨越和不吸附的近邻道路 | 只有允许的同层连接连通，高架及近邻不误连 |
| AC-03 | 道路包围大面积土地并推进月份 | 自动生成合法内部支路；获得实际接入的部分可开发，无接入腹地保持未开发 |
| AC-04 | 同一世界切换缩放、视图和导出尺寸 | 长度、面积、人口和价格不变 |
| AC-05 | 设置有限迁入和外部经济需求后推进城市 | 先出现可行开发与施工，竣工后匹配入住和岗位 |
| AC-06 | 建成住宅但没有家庭入住 | 住房容量增加，实际人口不随之自动增加 |
| AC-07 | 为两岸居民与岗位设置无桥河流，再添加桥梁 | 无桥时按网络不可达；建桥后可达性按实际路径变化 |
| AC-08 | 删除某社区唯一接入道路 | 显示失联，出行和开发受影响；建筑不被立即凭空删除 |
| AC-09 | 铺轨并建站，但不创建运营服务 | 没有乘车旅程和虚构客流 |
| AC-10 | 创建可替代长距离汽车通勤的巴士，再提高班次 | 候车和方式选择响应；车队及运营成本相应变化 |
| AC-11 | 设置需求超过容量的公交线路 | 出现滞留、额外等待、改道或未完成出行 |
| AC-12 | 两条地铁交叉，先不建换乘连接，再补建 | 补建前不可直接换乘，补建后计入实际换乘成本 |
| AC-13 | 增加一个有效换乘的完整公交旅程 | 完整出行数为一次，上车人次按实际乘车段增加 |
| AC-14 | 在低需求区域新设站点 | 不保证立即高客流、涨价或高层开发 |
| AC-15 | 在住房短缺场景增加可行住房供应 | 竣工后进入供应并影响入住、空置和租金调整 |
| AC-16 | 保持工资不变，持续提高某区住房成本 | 超负担家庭按阈值搬迁或退出，目的地受实际供给约束 |
| AC-17 | 向办公集聚区提供持续需求和有效交通，推进较长时期 | 可逐步形成中心；办公、商业、密度和活动共同支持识别 |
| AC-18 | 只建设一组高层住宅 | 不因高度被认定为 CBD |
| AC-19 | 对主中心施加土地与交通约束，并改善另一节点 | 在合适需求下允许形成副中心，不要求每次必然形成 |
| AC-20 | 汇总全市人口、岗位、住房和出行，再下钻对象 | 汇总可核对，无重复人口、岗位占用或换乘重复出行 |
| AC-21 | 保存后继续模拟，再从该存档重复相同命令 | 在固定模型版本及容差下得到一致状态 |
| AC-22 | 从同一检查点创建有无新线路的两个方案 | 原存档不变，条件和结果可比较，优劣不预设 |

上述验收同时覆盖正向行为、无需求、无连接、容量不足和供给受限等边界。涉及方向性的模型测试应固定其他条件；涉及长期随机演化时使用明确种子、时间范围和合理容差，避免把单一随机结果当作普遍规律。

## 24 地形联动与自主生长规则

地形联动、曲线道路、自动补路和配套属于产品规则。自动生长默认开启，玩家可以只建设主要道路，再由系统按需求与约束形成支路、地块、建筑和配套。

**TERRAIN-001 地块地形摘要**

每块土地保存高程、平均及最大坡度、局部高差、邻水距离、景观指数、低地邻水代理指标、工程成本倍率、适宜性及高度上限。采样来自固定世界数据；低地指标不能称为洪水概率。

**TERRAIN-002 交通与工程联动**

曲线道路沿实际中心线采样高程，计算爬升、坡度、建设费用、自由流及步行耗时、有效容量。桥隧有独立结构成本。道路所导致的通勤和货运差异进入居民、企业及开发决策。

**TERRAIN-003 土地与开发联动**

坡地处理成本、可建范围、强度限制、景观和低地条件进入地价驱动、用途评价、预期收益、楼层和施工成本；不只是改变地图颜色。同样道路与种子在不同地形上应能产生不同结果，受月度价格限幅约束。

**TERRAIN-004 查询与统计**

地块详情显示地形及价格贡献项；地图提供坡度、建设成本、景观和低地指数图层；城市概况汇总地形工程支出、已开发地块平均坡度与相关人口暴露。人口、就业等经交通与土地市场间接响应地形，不机械地给每个指标乘同一系数。

**AUTO-001 自动社区支路**

主路预留接入空间；每月有上限地增长社区支路。线路候选比较地形成本和转弯代价，避开水体、陡坡、保护区、既有建筑和公共空间。生成道路保留来源、父道路、稳定 ID，进入正常拆分、寻路、财政、选择及拆除流程。

**AUTO-002 入口、院内及邻里小径**

每栋建筑自动生成到临街道路的入口小径；有足够退界空间的住宅生成院内路径。近邻建筑之间可生成不穿水、不穿建筑的步行连接，并实际接入步行与公交接驳图。小径不能无条件穿越快速路或形成隐形跨河捷径。

**AUTO-003 多样建筑与开放空间**

自动形成住宅、商业、办公、工厂与仓储，以及公园、广场和随人口需求增长的学校、诊所。建筑的轮廓、占地、楼层、高度、屋顶和容量有用途及个体差异，遵守地形限制。公园和广场是真实占地、具有容量和维护成本的公共设施，其地块不能同时开发普通建筑。

**AUTO-004 恢复与控制**

自动生长可暂停，生成对象和尝试状态随存档保存；恢复后按同样种子与命令得到同样结果。旧模型迁移保留既有建筑，明确提示后续采用新版规则。画路失败保留控制点；在绘制、平移等工具之间切换保留未提交草稿。

新增验收：曲线端点与控制点稳定；道路长度按曲线计算；平地/坡地同路段的工程费与通行时间不同；仅绘制主路并推进即可出现支路、公园、广场和多种建筑；建筑不压占公共空间；邻里小径存在对应寻路边；存档继续结果一致。

## 25 建筑形态与街区完整性

小街区应按完整土地范围规划，允许单一用地、连续沿街建筑、围合庭院、折转小巷和侧园等形态。共享空间必须占有真实土地并保留通行，不能用建筑纹理伪造院落。建筑数量应受边长、用途与实际可用面积约束，不能始终套用两栋或四栋布局。

沿街建筑优先保持临街面，面积限制主要作用于进深；不得将所有建筑等比缩小到地块中央。独立工业厂房和仓库优先采用沿道路方向的规整主体，容量、费用和楼面面积依实际轮廓计算。

既有建筑、明确用途、保护地、公共空间和更新预留不得被自动布局替换。临街接入、院内路径和邻里步道必须形成可通行的图边；围合庭院应沿合法折线路径计时，不能穿墙直连。

## 26 设施与显示规则

机场、港口、铁路客站、停车设施和城市公共设施使用真实占地、明确接入与独立财政记录。具有外观不代表已经具备对应运输、能源、供水或应急运营模型；每类设施必须标注实际参与的计算。

地图与精细视图读取同一城市。普通建筑屋顶、设备、景观、车身和服装可以程序化生成，但外观随机性应稳定，不能影响经济随机序列、改变合法占地或增加容量。

实时交通、信号及行人应共用运行时钟，暂停时保留状态。高速运行允许有标识的画面抽样，必须完整执行跨月城市结算；不能把抽样通过数当作跳过时间的真实总量。
