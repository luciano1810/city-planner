# 时间、信号与实景交通

## 1 三种时间语义

项目同时包含连续日历、逐日施工、每周经济和场景光照。连续日历决定当前日期、开竣工日期和每周结算；代表日交通用于每月经济分析；实景人车是画面活动样本；光照允许单独预览。

它们需要协同，但不能混为一套统计。改变太阳位置不应重新匹配岗位，画面车辆通过量也不能直接当成全市代表日旅程。

主要实现为 [simulation.py](../city-planner/backend/city/simulation.py)、[signals.py](../city-planner/backend/city/signals.py)、[pedestrians.py](../city-planner/backend/city/pedestrians.py) 和 [simulation-driver.js](../city-planner/renderer/simulation-driver.js)。

## 2 日期与统一运行控制

城市以 2026 年 1 月为日历基准，按公历月份长度推进，包含闰年二月。状态保存完成月份、月内秒数和累计模拟秒数。

界面只有一套开始、暂停和速度控制。默认暂停，加载后也保持暂停。暂停保存日历、人车位置、信号阶段和步态；不会将场景重置为早上或重新抽取路线。

| 速度档 | 每现实秒目标推进 |
| --- | --- |
| 实时、2×、3×、5×、15×、60× | 1、2、3、5、15、60 秒 |
| 分钟、小时 | 5 分钟、1 小时、6 小时 |
| 天、周、月 | 1 天、7 天、30 天 |

这是目标速度，实际推进受计算性能限制。接口单次目标最多 31 天，交互界面每个响应实际最多推进一天，并保留未完成的目标时间；月档是固定秒数，不等于跳过任意公历月份。

没有运营公交线路时，同一起终点的步行／驾车路径及费用跨收入和时段复用，方式选择仍按各户收入计算，交通分配仍逐户、逐时段累计。超过可接受时间的步行路径无需展开。路径缓存同时限制为 4096 条记录、65536 条路径边，路网或拥堵成本重建时清空；有公交时继续使用班次、换乘和运力检查。

住房需求按是否有车共享通勤排序，再按收入筛选可负担住房；无空缺岗位不参与住房分配候选计算。公交图等于步行图时，经济服务范围复用步行时间，受限通勤仍要求真实乘车边才能计为公交。经济服务范围权重在同一路网和政策下共享，各市场的需求与容量余额独立，开发预留后清除需求查询缓存。自动存档使用快速无损 gzip 压缩，仍在返回月结算结果前原子落盘；手动存档保留较高压缩率。

## 3 逐日施工、每周结算与事务

建筑开发每七天评估一次。通过评估的项目先预留地块、住房及岗位容量，标为待开工；同一批项目分散到随后七天逐栋开工。待开工建筑不渲染成工地，不提供可入住住房或在岗职位，但计入未来供给，避免重复建设。

每栋建筑持久化具体开工日期、竣工日期和施工进度。工期按实际公历月份换算为天，并加入稳定的项目差异。每日零点更新施工进度，到期逐栋交付。三维和 Canvas 视图从场地准备逐步显示主体结构；加层保留原有建筑，仅新增部分逐日施工。更新项目的拆除、施工和交付也按具体日期推进。旧存档的在建项目保留剩余工期并迁移为日级计划。

财政、迁入、就业匹配、市场价格、开发评估和统计每七天结算一次，周界不随月界重置。原来按月定义的费率、增长额度、价格平滑和持续时间参数按实际经过天数折算，跨月、闰年二月使用对应月份的天数；整数项目及迁入额度保留小数余量。月末仅更新月度基础设施节奏及归档报表，不再重复扣款或批量启动普通建筑。

交互界面使用 [monthly.py](../city-planner/backend/city/monthly.py) 的后台准备通道（保留兼容文件名）。在每次周结算前一天，将独立快照交给子进程准备。其他日期直接处理轻量的施工事件，每个响应最多推进到下一个午夜。周结算准备不足时，日历仅推进到实际完成的阶段；仍可暂停、查询和保存。

准备结果绑定城市对象、月份和修订号。建设、离散步进或切换城市取消旧进程；失败不发布半成品。周界与月界重合时也只提交一次。暂停时后台可以完成准备，但不会自动改变城市。完整提交后原子自动保存，周内手动存档包含所有施工计划和小数余量。

“推进月份”也逐日处理同一套施工与每周结算，不再调用独立的月末批量开发逻辑。跨日、跨周失败恢复整个请求前的权威状态、随机状态、交通运行态和编辑栈。

## 4 前端请求串行

唯一调度器累计目标秒数和对应光照秒数，同一城市同时最多发起一个推进请求。速度切换影响之后积累的时间，不把之前积压强行按新倍率重算。

增量响应通过 `advancedSeconds` 返回实际接收的日期时长；未接收部分回到当前运行会话的积压中。光照按本次请求已消费，不随日历积压重复播放。暂停、切城后不重新加入迟到响应的积压。界面显示周结算阶段和完成比例，超过 0.8 秒仍保留请求等待提示。

暂停后允许最后一个已发请求返回并接收其结果，随后停止继续请求。切换城市后忽略旧城市迟到响应；页面进入后台自动暂停，返回后由用户继续。计算失败停止推进并显示原因。

这些规则解决重复结算、乱序覆盖和请求返回时跳变的问题，不保证机器一定达到所选倍率。

单次请求等待超过 0.8 秒时，界面显示“计算中”，完成后自动继续；用户在等待中暂停，则接收本次结果后保持暂停。没有运营中的公共交通区段时，可达性统计复用不随时段变化的步行和驾车结果；有公共交通时仍逐时段计算班次等待和服务时间。

## 5 光照时钟

光照单独保存为 `sceneTimeSeconds`。低于每天/秒的速度档，光照跟随模拟秒数；达到或超过每天/秒时，以接近现实速度推进，避免太阳高速闪烁。切换速度不重置太阳位置。

手动拖动当天时刻会暂停运行，只改太阳和夜景，不改变城市日期、月内经济进度及人车活动状态。离散月步进也不强制改变观察光照。

## 6 实景活动的两种来源

### 道路分时流量展示

在“观察 → 交通 → 道路流量”中，可切换高峰最大值、早高峰、平峰和晚高峰。早晚高峰各按 2 小时折算车辆/小时，地图颜色表示小时流量与有效容量之比：不超过 60% 为绿色，60%–100% 为橙色，超过 100% 为红色。容量沿用交通分配中的地形及信号修正。平峰是活动抽样，只显示抽样车辆数，以蓝色深浅表示相对流量，不计算小时流量或饱和度。

点选道路可查看各时段车辆数、小时流量和饱和度。每列取该道路各路段的最大值，避免把同一车辆经过的连续路段重复累加。这些是最近一次典型工作日交通分配结果，随周结算或触发重新分配的操作更新，不是画面车辆的实时通过量。分时结果随存档保存；旧档缺少的时段数据显示“—”，重新分配后补齐。

“观察 → 交通”还提供以下专题视图，各自附带单位、颜色阈值和无数据说明：

| 视图 | 展示内容 |
| --- | --- |
| 道路饱和度 | 小时车流 / 有效容量，可选择早高峰、晚高峰或峰值 |
| 预计通行速度 | 路段长度除以模型通行时间，包含拥堵和信号等待；双向路取等待更长的方向 |
| 道路延误 | 相对含地形影响的自由流时间，额外增加的拥堵与信号等待秒数 |
| 有效道路容量 | 基准容量经地形、信号修正后的车辆/小时 |
| 公交线路负荷 | 运营有效线路的峰值载客率，不按单个时段展开 |
| 站点客流 | 典型日上下车人次之和，以圆点大小、颜色表达；换乘可能重复计次 |
| 住宅通勤时间 | 同一住所内有通勤时间记录的家庭均值；无记录和失败旅程不按 0 分钟计算 |
| 公交岗位可达 | 30 分钟内步行与公共交通可达的岗位总量，不保证存在空缺 |
| 路网接入 | 地块接入状态，帮助发现失去接入的建筑与用地 |

速度与延误是依据既有交通模型推导的估算，不能当成实景车辆的测量值。平峰样本没有校准的小时流量，不提供平峰饱和度、速度或延误。道路详情同时提供最慢路段的预计速度、最大路段延误和最小有效容量；住宅详情提供有通勤记录和通勤失败的家庭数。

城市交通分配模式从已有月度需求和路段流量抽样。空城没有需求时不会凭空出现城市车辆和居民。验证模式可以生成受控人车，用于观察路口和排队，其数量不能计入人口、就业、票款或代表日交通。

网络改变、月度分配重建、来源切换或显式重置可能生成新的兼容样本。普通暂停和继续不重新抽样。

## 7 低速精细步进与高速抽样

常规实景使用约 0.1 秒步长处理跟驰、信号和步行。是否抽样最终取决于单次请求推进量：超过 10 秒时，日历推进完整时长，人车仅计算末尾最多 3 秒的样本。

高速时信号定位到新时刻并保留路口清空保护；界面显示高速抽样。样本中的等待、通过和过街累计不代表被跳过时段的全部活动。施工每日更新，人口、价格和财政仍按完整的周结算处理。

回到低速后从当前样本继续，不把交通或日期归零。这是一种有边界的画面采样，不是全量微观交通加速求解。

## 8 路口信号

符合条件的实际地面路口按进入方向组织受保护相位，包含绿灯、黄灯与全红清空。当前默认分别为 12、3、3 秒，可随校准保存。桥隧中跨或没有实际接点的交叉不布置信号路口。

车辆进入前检查当前目标路口许可、前方跟驰和清空条件。已获准进入的车辆需要释放占用后，冲突方向才能安全使用。相邻路口各自保留许可及占用，不能把上一个路口的许可复用到下一个。

期望信号等待和有效绿灯比例进入代表日机动车成本及容量。实景放行与经济分配共享信号规则来源，但当前不是基于实景逐车通过来重新求解全部通勤。

## 9 实景车辆

车辆沿合法路线运动，使用距离、速度、跟驰间隔、停止线和路口占用。不同车身外观由稳定散列决定；车辆数量、车漆和灯光属于显示表达。

当前不模拟完整变道、超车、驾驶人异质性、事故处理或逐辆公交上下客。车道箭头表达合法方向，不代表已经建立完整逐车道微观求解器。

## 10 行人图与过街

实景行人网络沿可步行地面道路两侧人行道生成，曲线与转角避开车行道和建筑。斑马线位置及宽度与显示路口使用同一净距规则。

进入斑马线前检查行人绿灯、剩余通过时间和车辆清空；已经开始过街的人继续走到对侧，车辆检查行人占用。没有独立信号保护的路口不生成未保护的实景过街动作。

快速路、高速公路、桥梁和隧道当前不布置这套实景行人。它的范围不能被当成完整经济步行可达范围；后者还包含建筑入口、邻里路径和公共交通接驳。

## 11 行人运动和外观

同向行人保持间距，双向流在中心线两侧错开。步态按实际走过的距离推进，等待时停止摆臂和迈步。身高约 1.60–1.83 m，16 套稳定外观组合服装、肤色、发色、鞋帽和背包。

精细三维人物参与深度遮挡和阴影，Canvas 路径用同源服装图集表达。外观不新增家庭或改变劳动者数量。当前路线是确定性街区活动流，不逐人映射居民完整通勤链；验证模式人数上限为 180。

## 12 保存与恢复

存档包含模拟时钟、光照、速度、交通来源、路线段、距离、等待、路口占用和行人步态等运行状态。恢复后暂停，允许在兼容路网下继续；旧档缺少相关字段时补建默认状态。

旧单路口占用等运行结构保留兼容路径，但模型迁移不承诺跨版本逐秒活动完全相同。恢复确定性的前提是相同模型、有效米制地形、完整状态和相同后续输入。

## 日历回归检查

在 `city-planner` 目录执行 `npm run test:calendar` 可验证逐栋开竣工、施工进度、跨月周费率、读档继续、后台结算提交和整次请求回滚。安装 Playwright 后可运行 `npm run test:calendar:visual`，保存两种渲染器的施工阶段截图，并验证实际浏览器暂停和跨月运行。测试使用独立临时存档，不操作玩家存档。
