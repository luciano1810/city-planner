# 统一铁路实现与操作

本说明描述当前代码行为；目标与验收要求见[重构需求](metro-train-reconstruction.md)。地铁、火车和跨类型直通共用轨道与运营模型，货运、港口及电车仍沿用各自范围。公交继续使用原有三个菜单入口。

## 操作入口

在「公共交通 → 铁路」中建设车站、轨道、道岔、折返设施和越行轨道，然后新建线路或进入铁路管理。

1. 建站时直接选择地下、地面或高架以及 1–8 个站台。「尺寸与朝向」可展开调整站台长度和旋转；移动鼠标预览占地、站台端口、入口和费用，点击地图或 Enter 建设。已有建筑的位置只允许地下站，建筑及入住状态保留。
2. 地下站自动寻找合法室外入口，也可在预览中移动入口。重叠建筑提供内部入口勾选；只连接明确关联的建筑。没有合法人行接入时拒绝建设。
3. 使用轨道工具连接具体编号站台的端口。新轨道的同层交叉不会自动成为道岔；分支、交叉换线需要真实道岔。跨层连接沿用显式接入和坡道约束。
4. 开放式线路两端需要折返设施。建设设施先预览占地、连接和准确费用，再确认建设。新建线路时点击具体站台，或使用车站、站台选择器依次加入；Backspace 撤回，Enter 创建。途经火车站与地铁站的兼容服务自动标识为直通。
5. 铁路管理默认显示名称、颜色、车型、编组、配车和时段。自动配车填写目标班距；指定配车填写列车数量。首末班使用时间控件，跨午夜显示「次日结束」，全天可单独勾选。
6. 「停站与站台」选择各站平台或取消中间站停靠，支持重新排列停站。「高级设置」提供往返、各向环线、单向载客及空车回送、限速、停站时间和途经接点。统计和共享限制折叠查看。
7. 点击车站编辑名称、数量和入口。扩建前可预览费用；削减站台需先解除相关线路、接轨和列车占用。既有站台 ID 保持稳定，不自动改绑线路。平台摘要直接显示连接、折返、服务线路和占用，接口坐标及客流统计按需展开。

8. 「观察 → 显示公共交通线路（公交 / 地铁 / 火车）」控制地图与精细视图的运营线路叠加，默认关闭并记住本机偏好。线路沿真实路径，以白色外描边、线路色、白心站点、终点强调、共线并排和简洁色标呈现，参照苹果地图公共交通样式；关闭不改变车辆、客流或财政，也不隐藏建设草稿。
9. 运营数据内可选择实际采集日期，展开逐小时图及数值、各方向事件和实际发车数。车站编辑内可查看实际目的地、换乘站组及组内事件汇总；换乘距离阈值可在管理页「换乘规则」调整。入口移动时可设置朝向。

编辑失败时显示原因、保留草稿，不部分保存。线路草稿在刷新、切换和重新打开管理窗口时保留；成功保存后清除。改名、改色不要求故障线路先恢复通车。暂停或删除服务停止新发车，已经载客的列车保留行程快照。

## 状态与模块

| 模块或状态 | 职责 |
| --- | --- |
| `rail_infrastructure.py` | 站台布局、入口与通道、道岔和折返、越行轨道、换乘站组、建设和编辑校验 |
| `rail_services.py` | 车型、编组、实际轨道寻路、停靠与通过、共线运力分配、公共交通图、查询 |
| `rail_runtime.py` | 权威列车运行、资源占用、乘客群体、实际事件、日期归档和待结算票款 |
| `transit-overlay.js` | 公共交通线路地图叠加、共线错位、站点和线路标签；不改写运营几何 |
| `rail-ui.js` / `rail-ui.css` | 地图建设与站台选点、预览、线路及车站设置 |
| `stops[].platforms` / `entrances` | 稳定的站台、轨道接口、出入口与建筑引用 |
| `railInfrastructure` | 调度设施、显式站内通道、可达换乘关系和站组 |
| `railRuntime` | 模拟时钟、列车、乘客、预占资源、发车时刻、当日及历史事件 |

服务层提供 `rail_preview`。命令包括 `rail_station`、`rail_entry`、`rail_facility`、`rail_passage`、`rail_rules`，线路继续使用 `line` / `line_update`。物理修改进入既有原子命令和撤销、重做流程；预览不扣费。

站台的中心线对应带双向股道的岛式站台，编号站台拥有两个方向的站台面，不等于单股道。每个站台拥有明确的轨道对象，线路记录其 ID。站台本体轨道不能独立删除或拖动；需通过车站编辑调整数量。

## 路径、换乘与共线

寻路统一读取 metro/train 实际网络，并遵守单行和层级。新建管理轨道在无道岔交叉处隔离，接通的端点可以延续。环线要求真实闭合路径，不能以重复往返同一区间冒充环线。单向载客服务需要合法回送路径。短线通过选择实际服务区间及合法端点折返实现。

跳停不产生该站上下车。建设越行设施会生成实体旁通轨道和两端道岔；经过该跳停站的路径使用旁通轨道，而非只改变速度。每条服务先计算运行周期及目标车数，再按共享区间和设施占用修正可提供班距，避免多条线各自取得同一份独立容量。

运行时按整段用户建设的轨道对象及方向预占资源，道岔互斥，所有经过的站台（包括未建设旁通的跳停站）按物理股道方向占用，而非线路的站序编号；折返设施独占；整条下一停站区间一次取得所需资源，释放时包含安全间隔。等待列车按到达顺序竞争。站内等待继续占用站台，环线保留空位以避免满环互锁。当前运行区间被列车占用时拒绝直接编辑或删除；跨模拟时间的撤销、重做也校验当前资源占用，不倒退真实客流时钟；前方断轨会保留列车与乘客，修复合法连接后再继续。

换乘依赖实际步行图。入口到人行道的精确投影进入图中，水平步行与层间通行均计时。邻近站是否合组按实际最短步行距离判断；站组只是展示分组，不生成零时间边，A–B–C 成组也不意味着 A–C 可以瞬移。隔离地下站厅可预览并付费建设显式通道，关闭后重新计算可达性。

## 客流、时间和财政

典型日需求来自现有城市出行分配；运行模块按带日期的意图生成乘客群体，记录进站、上车、下车、出站、换乘、满载未上车和未完成出行。候车与车上人数来自同一份运行状态，动画不回写计数。站内自由活动人数未模拟，界面明确区分。

直通乘客保留车上状态，不在地铁站和火车站边界重复上车或换乘。实际发车在取得进路并离开始发站时计数，往返两个方向分别计班次，空车回送不计载客班次。一次铁路出行在首次实际上车时收取票款；换乘后的上车计入乘坐人次，外部进出站仍按完整旅程计数。满载未上车表示一次实际尝试，不等同于独立人数。实际历史只记录采集过的日期，保存每日 24 小时及分方向事件；历史旧记录缺少小时数据时显示尚未采集，不补造历史。大乘客群体可以按剩余容量分批上车，剩余人员继续候车。

列车、乘客和资源占用随模拟时间推进，独立于视觉抽样倍率。每天 0 点归档与结算，跨午夜时段继续运行。末班截止后不再新增发车；已发列车完成行程。运营调整影响新行程，在途载客列车保留合法旧行程直至结束。

实际票款在每日结算使用 `pendingFare` 收取一次，代表日出行不再重复产生铁路票款。车辆租赁、运行距离及站台、轨道、设施维护进入现有财政链路；同一物理轨道或设施不因共线重复建设和维护。线路、入口和接轨通过公共交通可达性影响就业、入住及后续开发，不直接给站点附近土地强加增值。

## 参数与费用

以下为游戏模型默认值，不代表现实工程标准。

| 项目 | 默认值 |
| --- | --- |
| 站台 | 2 个，长 120 m；可选 1–8 个、60–360 m；编号间距 14 m |
| 建设层级 | 地下 -1、地面 0、高架 1 |
| 建站主体费 | `(500000 + 站台数 × 长度 × 1800)` 元，地下乘 1.6，高架乘 1.3 |
| 新增站台 | 按新增数量 × 原长度 × 1800 × 层级系数收费；缩减不退费，再扩建重新收费 |
| 入口和接入通道 | 每处 45000 + 水平长度 × 900 元 |
| 道岔 / 折返 | 25000 / 80000 元 |
| 越行设施 | 实体旁通轨道费用加 100000 元设施费，包含两端道岔 |
| 站厅间通道 | 80000 + 水平长度 × 1200 + 垂直长度 × 4500 元 |
| 换乘阈值 / 入口搜索半径 | 实际步行 300 m / 140 m |
| 平面 / 垂直通行速度 | 80 / 24 m/min，层高 8 m |
| 安全间隔 / 折返 | 30 / 90 秒 |
| 新建轨道坡度 / 最小曲率半径 | 6% / 30 m；每跨一层坡道至少约 134 m |
| 市域车型 | 每节 150 人、20 m、最高 100 km/h；每节每月租赁 6500 元 |
| 城际车型 | 每节 110 人、24 m、最高 140 km/h；每节每月租赁 8500 元 |
| 运营范围 | 编组 1–12 节、指定配车 1–100 列、目标班距 1–120 分钟、时段 15 分钟至全天 |

## 兼容与模型边界

旧存档缺少新铁路状态时初始化空运行态，不伪造历史事件。旧点式铁路站继续使用原轨道附件与历史逻辑折返，避免读档即拆线；不会自动变为具有实体占地及入口的多站台车站。新建设车站使用完整平台模型。存档保留乘客、车上人数、预占和发车状态；恢复后继续而非重新生成同一天旅程。

当前是可解释的离散运营模型：

- 使用保守的整轨道、整停站区间预占，未实现连续移动闭塞、加减速曲线及区间中的动态追越。越行旁通真实存在，但不模拟铁路级精细调度优化。
- 乘客由代表日出行意图生成，未把城市每名居民改成连续全天活动个体。公交仍沿用自己的出行与车辆模型，铁路接驳读取既有公共交通链路。
- 显式通道按几何、障碍和距离校验，没有地下施工地质、建筑结构承载或真实隧道掘进模拟。
- 运营、名称等不改变几何的编辑复用基础网络缓存；物理编辑仍触发既有网络重建，未变的步行图复用换乘查询缓存。尚未完成大型轨道网络的全量增量拓扑系统，当前规模测量不能外推到任意城市。
- 典型日分布与实际小时／日期统计分列，图表不把估算当作实际。途经接点表单目前每个出发站选择一个接点。
- 快线、有效环线、复杂分支以及高负荷故障恢复仍应持续扩展真实界面组合场景；不能把已有单元覆盖视为全部需求场景均经人工操作验收。

复现工具为 `npm run test:rail-system`、`npm run test:rail-system:visual`、`npm run test:rail-system:lifecycle`、`npm run test:rail-system:overlay`、`npm run test:rail-system:development` 和 `scripts/benchmark_rail.py`。特定运行结果、环境、截图索引及未覆盖项单独放在[完成审计与全流程验证](../experiments/rail-completion-audit.md)，不混同为设计保证。
