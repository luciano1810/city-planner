# 统计、存档与方案比较

## 1 数据解释契约

城市观察不仅显示数值，还应说明数值的单位、时间范围、空间范围、样本分母、模型和是否估算。同一事实在全市面板、地图详情、历史、CSV 与 JSON 中需要一致。

指标由 [reporting.py](../city-planner/backend/city/reporting.py) 定义，城市和空间统计主要由 [engine.py](../city-planner/backend/city/engine.py) 与 [urban.py](../city-planner/backend/city/urban.py) 汇总，存档及比较由 [service.py](../city-planner/backend/city/service.py) 管理。

## 2 时间口径

| 口径 | 示例 | 解释 |
| --- | --- | --- |
| 月末存量 | 常住人口、可用住房、岗位、土地估值 | 当前月份结束时的实际状态 |
| 模拟月流量 | 迁入迁出、税收、维护、行业开闭 | 这个模拟月内的变化或账目 |
| 累计至月末 | 建设支出、累计更新支出 | 从城市起点累计，不能再次按月相加 |
| 典型工作日 | 出行、上车、货运、里程与通勤 | 当前月代表日分配，不是全月全量观测 |
| 年度汇总 | 人口期末和当年收支、迁移 | 区分存量快照和全年流量累计 |
| 实景运行样本 | 画面等待、通过及过街 | 与代表日统计分离，高速时还有抽样 |

代表日费用推算到月度时使用每月代表工作日参数，默认 22 天。不能把典型日客流直接标为当月乘客，也不能对月末人口累加得到年度人口。

## 3 核心指标目录

| 系统 | 主要指标 |
| --- | --- |
| 人口住房 | 人口、家庭、迁入迁出、城内搬迁、待安置户、已交付及在建住房、空置 |
| 就业经营 | 设立岗位、实际就业、空缺、失业、行业群组、经营开闭与迁址 |
| 土地建筑 | 可建与已开发面积、楼面面积、用途、层数、楼龄、容积率和密度 |
| 市场负担 | 土地估值分位、用途租金、物业估值、住房与综合支出负担 |
| 出行 | 完成及失败旅程、目的、方式、平均/中位/P90 通勤、距离与费用 |
| 公共交通 | 完整旅程、上车、换乘、分站客流、等待、拥挤、车队和运营费用 |
| 道路与区域 | 路网里程、流量与拥堵、区域客流、吨位、货车次及短驳 |
| 可达性 | 岗位、空缺、劳动力、服务机会及不同预算和群组结果 |
| 财政 | 资本分项、资金、税收、票款、道路站点设施维护及公交运营 |
| 环境地形 | 工程支出、坡度、景观、污染代理、低地暴露与排放估算 |
| 城区更新 | 城区边界与阶段、进行及完成项目、支出、安置与迁出 |

新增指标必须在定义表中有单位，否则汇总导出应报错，不能输出无解释的新字段。

## 4 分母与零值

方式占比使用已完成完整旅程作分母，失败需求单列。公共交通主方式按最长乘车距离识别；一趟换乘不能同时重复计为多个完整旅程。

通勤指标来自符合目的与完成状态的样本。无通勤样本时应为缺省或无数据，不能写成零分钟优质通勤。没有家庭的城市不能显示有意义的失业率或住房负担。

土地分位当前按地块等权计算，不是按土地面积加权的全市平均。人口和岗位密度要说明分母是全世界面积、城区面积还是已开发面积。

## 5 空间范围与下钻

观察提供全市、城区、矩形范围和具体对象。范围统计目前按地块中心归属，而非将所有跨边界多边形精确分割计量；阅读边界附近结果需采用这一口径。

地块和建筑可查看接入、用途、容量、占用、地形、价格贡献和开发原因。道路、站点、线路显示各自长度、流量、成本和失效原因。城区显示实际边界、用途、日夜人口、岗位、流入流出及价格分位。

等时范围沿真实网络成本选择可达地块，包含接驳与等待，不是任意半径圆。收入组、汽车条件和早/平/晚时段可以形成不同可达机会。

## 6 流向和环境指标

活动 OD 由实际旅程按空间、目的、时段及主方式汇总，近景可以抽样显示路径。迁入、迁出与搬迁流按实际人数记录，地图外部位置是有标识的抽象门户。

汽车排放使用车公里和可配置系数估计，默认 0.17 kg/km。污染、噪声及低地邻水是游戏代理；不能标成实测浓度、洪水概率或完整生命周期排放。

## 7 历史与事件

每月保存汇总指标和模型标识，每满 12 月追加年鉴。地块历史保留最近 240 月，事件保留最近 250 条。后续模型或参数改变不能用当前结果重写旧月历史。

建筑竣工、设施、企业和中心形成等事件可以定位对象。空置、拥堵、公交紧张及通勤改善等阈值事件通常需持续 3 月，同类事件有约 12 月冷却，减少噪声。

事件是解释入口，不构成对因果关系的证明。城市整体事件可以没有单一地图位置。

## 8 CSV 和 JSON

CSV 面向表格分析，列需要注明单位、时间口径及估算属性，并保存模型版本。JSON 提供设置、参数、指标定义、城区、OD、账目及必要元数据，便于复核。

城市完整存档与统计摘要是不同格式：摘要不能恢复整座城市，PNG 更不能代替地形和状态。导出时应区分地图图片、统计数据和完整城市。

## 9 存档内容

完整城市快照包含格式及模型标识、实际地形、城市权威状态、校准目录、随机状态和运行态。它覆盖道路站点线路、地块建筑、家庭工作、设施与种子、公共路径、城区、规划与更新、资金账目、历史事件以及日历光照。

只保存种子不足以恢复城市：生成器可能变化，后续随机过程和手工命令也无法从初始种子唯一重建。恢复需要读取实际数据并校验，再建立派生网络。

## 10 写入与加载

默认保存目录为 `~/.shanhai/saves`，可用 `SHANHAI_DATA_DIR` 指定。文件使用 gzip 压缩 JSON。写入先建立临时文件、刷新并 `fsync`，之后原子替换；新建模式拒绝覆盖同名有效存档。

导入、加载先检查格式、数值、集合、ID、住所与岗位引用、容量、几何和地形，再建立会话。非法数据不得污染当前城市；读取失败应保留原有存档。

当前载入还设置数量保护上限：道路 2000、地块 30000、家庭 100000。它们是输入保护，不是性能承诺。整体字节上限另由高度格式模块规定。

## 11 迁移与兼容

当前模型标识为 `shanhai-city-12`，可识别城市模型 1–11 的迁移路径。迁移补充新增字段及默认参数，尽量保留既有建筑、布局和已存校准，并标注后续采用新模型规则。

城市模型兼容仍要求实际地形通过 `float32-le-meters` 解码。缺失高度编码的历史存档会失败；不能将“支持城市字段迁移”写成所有历史存档均可直接使用。

迁移不自动搬动旧建筑、重跑历史或重新塑造楼群。没有分项的旧建设支出保留为历史未分项，不能伪造原始分类。跨模型继续演化也不承诺随机结果逐项一致。

## 12 检查点、分支与比较

编辑撤销处理同一批暂停建设；磁盘检查点保存完整状态；分支从共同初态建立独立方案。三者的作用不同，不能依靠撤销模拟来代替方案分支。

分支记录共同初态身份，原方案不被分支编辑修改。比较读取参考存档，检查共同检查点、月份、情景设置、模型迁移和校准参数，条件不同给出明确警示。

当前比较人口、住房、岗位、就业、通勤、可达、公交上车、土地租金、空置和费用等，并对共同地块给出差值。不存在共同 ID 的新地块不能强行逐块配对。

## 13 结果解释与性能边界

即使共同初态和期限一致，方案建设也会改变后续机会与随机消耗，不能保证分支中的随机事件逐个配对。比较提供观察差异，不自动证明某条线路导致所有变化。

可支持的规模需要在固定模型、设备、数据和精度下测量。历史日志留在 `experiments/`；某次万栋渲染流畅不能证明十万人口月结算可玩，也不能用旧模型耗时担保当前性能。
